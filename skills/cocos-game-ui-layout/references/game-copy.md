# 游戏内文案

适用于玩家可见的 HUD、按钮、弹窗、奖励和状态反馈。默认让图片、图标、数字、符号和视觉状态表达含义，文字只补充无法直接看懂的信息；不是把解释句缩短后继续铺满界面。

## 表达选择

- 奖励、消耗、数量、倍率和进度优先用对应图标与数值；增减保留正负号，倍率使用 `x{value}`，进度可用 `3/10` 或进度条。
- 含义清楚的图标不再附带重复标签。必须有文字时使用短名称、短动作或短状态，如「领取」「升级」「已满」，避免完整解释句。
- 不熟悉的机制、首次必要引导或有实质后果的操作保留最少的必要说明，按需呈现。不得为精简而丢失奖励类型、消耗对象、条件或操作后果。
- 数值要与对应图标相邻并形成同一信息组；余额、价格和变化量使用清晰上下文区分，不能靠颜色或孤立数字猜含义。图标控件保留无障碍名称，该名称不必成为可见文案。

| 意图 | 优先表达 | 避免重复解释 |
| --- | --- | --- |
| 金币奖励 | 金币图标 `+100` | 获得 100 金币 |
| 钻石消耗 | 钻石图标 `-20` | 消耗 20 钻石 |
| 奖励倍率 | 奖励图标 `x3` | 获得三倍奖励 |
| 收集进度 | 目标物图标 `3/10` | 已收集 3 个，还需收集 7 个 |

示例用于说明表达方式，不固定项目的资源、数值或界面内容。

## 工作流接入

在现有 GDD、场景规格或 `visual-design.md` 中按当前场景与状态区分两类内容，不另建审批门：

- **内部规格**：规则、条件、计算、操作后果、设计理由与验收说明。用于理解和实现功能，不作为画面文字来源。
- **玩家可见表达**：对应图标/图片、数字或符号、必要的短标签及其显示条件。列明实际允许出现的文字；无需文字时明确为空。动态数值标明数据来源、格式与效果图示例值，必要引导标明何时出现。

例如内部规格可以解释金币结算规则；玩家可见表达只交接「金币图标 + 本次收益（带正号）」及数据来源。效果图采用代表值 `+100`，实现读取真实收益，不把规则段落变成奖励提示。

### 效果图生成

全局三候选、场景主效果图和弹窗宿主上下文图在生成前都读取同一份玩家可见表达。将内部规格标为理解用途，将实际可见文字单独列出；不能仅把 GDD 全文交给生成器并要求“按策划显示”。所有候选使用相同内容与示例数值，只变化当前探索范围内的视觉方案。

实际发送的提示词必须包含以下约束，并填入当前场景/状态对应的可见内容：

```text
游戏画面优先用图片、图标、数字、符号和视觉状态表达信息。
内部玩法规则、功能说明、设计理由、验收说明及本提示词的说明文字仅用于理解，不得绘制到画面。
只绘制本次明确列出的可见文字和示例数值；可见文字列表为空时，不添加说明句、标签或占位文字。
图标与数值已表达的信息不再重复写成句子，不自行增加规则介绍、功能副标题、教学段落或提示面板。
必要的引导、条件与操作后果按已定义的显示状态呈现，不擅自删掉必要语义。
```

在实际提示词中注明可见内容的现有文件/章节来源，生成记录按现有字段保存完整实际提示词，不增设 Schema 字段。先确定最小表达，再安排文字与布局；不要生成满屏说明后再压缩字号。是否实际画对由用户看图确认，提示词含有约束不代表画面通过。

### 资源拆解与界面实现

冻结效果图之后，文本拆解只登记目标中实际存在的玩家可见文字与数值，不从 GDD 追加说明节点。原子资源提示词继续忠实还原所属区域，不能把全局效果图的文案精简规则当作删除冻结文字的指令；图标、皮肤不附加业务说明，动态数值不烘焙进固定图片。

V4 正式界面消费 V2 确认的可见表达和文字/资源节点。`text_decomposition` 的 `content/source` 指向实际显示内容与来源；`node_presentations[layout_node_id].text` 填入对应短标签或代表性数值，不填业务描述。运行时 Creator `Label`/`RichText`、本地化键和动态更新读取同一表达与真实数据，不能直接绑定 GDD/brief 的描述、设计理由或验收字段。此规则覆盖按钮、HUD、弹窗、Toast 和奖励浮字；普通资产和无效果图路径同样适用。

本地化保留相同表达与显示条件，不把符号重新扩写成解释句。`longest_copy` 和长文案测试使用实际必要文案的最长翻译或边界输入验证适配，不要求给正式画面添加说明段落。编辑器操作、拆解标注与内部审阅说明不属于游戏内文案。

### 检查与返修

生成前核对实际提示词中的可见内容与内部规格分离；实现时核对文本配置、绑定来源与适用状态，不以字数、关键词或 `copy_style` 字段判定语义合格。

候选效果图冻结前及 V4 正式运行时提供实际画面和检查点：是否出现规格说明、重复句、额外标签，数值是否归属明确，必要条件与后果是否完整。显示效果由用户人工确认，代理不得自动分析截图或替用户填通过；复用原有确认节点，不增加独立文案确认。

已冻结参考中的文字不擅自删改。用户已明确要求调整时直接按当前范围修订受影响的目标与方案，再继续拆解或实现；只有存在实质未决取舍才询问。不靠隐藏文字、缩小字号或烘焙整屏掩盖问题。
