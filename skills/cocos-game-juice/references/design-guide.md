# Cocos 2D 游戏汁水感设计指南

本指南把 Juice（汁水感）定义为：玩家输入、规则变化、角色行为、环境反应和阶段成果，都获得及时、清楚、符合游戏气质的反馈，使操作有质感、结果可理解、情绪有回报。动作游戏强调力量，解谜强调解开的满足，经营强调成长，策略强调局势变化，恐怖强调紧张；不以特效数量、亮度或震动强度统一评价。

设计方法适用于主流 2D 类型；工程部分针对本仓库的 Cocos Creator 3.x。具体 API 按目标游戏锁定版本核对，不建立旧版本兼容实现。本文技术事实按 Cocos Creator 3.x.1.0 官方源码核实；所有时长、数量与幅度示例仅是调参起点，不是引擎标准、行业阈值或自动验收条件。

## 设计原则与玩法边界

1. 先使操作与结果可感知，再增强情绪。输入迟钝、结果含糊、危险被遮挡时，粒子不能弥补。
2. 以事件和因果为组织单位：准备 → 发生 → 结果 → 持续（适用时）→ 收尾，而不是散落的 Tween 和播放音效调用。
3. 反馈力度对应当前玩法的重要性。普通事件、重要事件和阶段峰值要有差别；高频小事件通常局部、短促、可合并。
4. 方向、速度、重量、材质和距离可以影响表现；成功、拒绝、危险等语义保持稳定。
5. 规则层确认事实，表现层消费结果；需要分阶段结算的玩法由明确状态机推进，不依赖装饰动画偶然完成。
6. 优先做主体反馈和声音，再增加粒子、镜头、时间及余波。真正的信息不足才增强，不强迫安静玩法爆闪或震动。

汁水优化与玩法手感相关但不是同一职责。实际击退、硬直、顿帧、输入缓冲、土狼时间、吸附范围、自动拾取和判定容错会改变规则、难度、节奏或公平性，由玩法及适用数值领域确定。视觉后坐力、局部形变和碎屑则通常属于表现；不能以“纯特效”静默改变判定。

## 通用反馈库

| 层级 | 可采用的反馈 | 必须表达的事实 |
| --- | --- | --- |
| 指向与焦点 | 高亮、轮廓、抬起、焦点声 | 当前指向或输入将作用于谁 |
| 选中 | 稳定标记、局部强调 | 已选择，区别于悬停 |
| 按下与释放 | 压缩、回弹、触点波纹、点击声 | 输入被接收，释放或取消 |
| 拖拽与放置 | 拿起、阴影、落点、吸附、落地轻弹 | 可放位置、合法性和最终归属 |
| 指令接受 | 动作启动、落点或路径标记 | 操作已接受，未必已完成 |
| 指令拒绝 | 原因标记、局部轻晃、短音 | 费用、冷却、目标等拒绝原因 |
| 准备与预告 | 蓄力、姿态、范围、瞄准线、音调变化 | 即将发生什么，何时可响应 |
| 动作发生 | 形变、轨迹、方向性粒子、声音起音 | 行为、对象和方向 |
| 接触与结果 | 命中点、对象反应、实际数值、状态变化 | 实际接触或规则结果 |
| 收尾 | 回弹、余波消散、声音衰减、姿态恢复 | 动作结束并回到正确状态 |
| 持续状态 | 燃烧、冰冻、充能、呼吸、工作动画 | 状态仍有效、进度或阻力 |
| 临界与结束 | 破裂、解除、就绪、倒计时完成 | 接近阈值、越过阈值、状态解除 |
| 数值变化 | 飘字、计数过渡、进度条、阈值强调 | 实际增加、减少与数量 |
| 积累与连锁 | 分段点亮、连击、音阶、触发来源 | 进展与因果顺序 |
| 成果兑现 | 汇聚、升级、解锁、结算 | 成果已确认及其意义 |
| 环境反应 | 草、水、脚印、尘土、物件扰动 | 行为确实发生在这个世界 |
| 界面转场 | 展开、收拢、焦点交接、上下文保留 | 进入、离开及当前可操作范围 |

信息反馈还包括合法落点、费用与收益预览、射程与路径、威胁倒计时、阻塞原因、效果来源。预览与实际结果要可区分；不得为了“看懂”揭示项目有意隐藏的谜底、敌人或随机结果。

## 运动接触与材质

| 行为 | 反馈候选 |
| --- | --- |
| 启动、停止、转向 | 倾斜、惯性、回摆、急停尘土 |
| 加速与高速 | 拖尾、残影、风线、声音变化、视差 |
| 起跳、下落、落地 | 压缩、拉伸、顶点姿态、风声、回弹 |
| 滑行、滚动 | 摩擦、旋转、轨迹、接触材质音 |
| 弹射、反弹 | 接触形变、释放拉伸、方向性粒子 |
| 拉伸、牵引 | 张力、绷紧、延迟跟随、释放回摆 |
| 轻重碰撞 | 局部小反应与更大的周围扰动分层 |
| 穿透、擦过 | 穿透轨迹、擦边火花、接近声 |
| 破坏 | 裂纹递进、剥落、碎片、形变和残留 |
| 液体 | 水花、涟漪、气泡、沉浮与湿痕 |
| 材质 | 金属清脆、木头沉闷、玻璃碎裂、泥地黏滞、雪地松软 |

粒子应从合理位置、朝合理方向发出。小球轻碰木板与重物击碎玻璃应有尺度和节奏差异。残留是否影响玩法必须明确，纯装饰碎片不自动成为碰撞体。

## 情绪与节奏

| 体验目标 | 动作与节奏 | 声音和视觉倾向 |
| --- | --- | --- |
| 力量、重量 | 明确准备、接触停顿、沉重收尾 | 低频、碎屑、短促位移 |
| 轻盈、敏捷 | 快启动、短收尾、流畅转向 | 清脆、细拖尾、轻小粒子 |
| 弹性、玩具感 | 挤压、拉伸、过冲、回弹 | 弹跳音、圆润形状 |
| 精密、机械感 | 精确吸附、分段、稳定节律 | 卡扣音、规则线条 |
| 黏滞、柔软 | 延迟、拖曳、缓慢恢复 | 湿润音、拉丝、柔性形变 |
| 舒适、治愈 | 温和展开、平稳汇聚、留白 | 自然材质、低对比变化 |
| 紧张、恐怖 | 预期延长、突然中断、节律不稳 | 环境声、局部异动、静默 |
| 荒诞、喜剧 | 夸张准备、意外收尾、节奏错位 | 反差音、特殊姿态 |
| 清晰、竞技 | 即时、短标记、稳定编码 | 易辨判定、低遮挡 |

一次重击可在确认当下同步接触、声音与目标反应，再展开碎屑，最后恢复；卡牌联动可依次强调卡牌、触发装备、目标结果。时序服务因果，不让无意义等待阻止下一次操作。

## 连续操作

| 操作 | 开始 | 进行中 | 完成、取消或中断 |
| --- | --- | --- | --- |
| 长按 | 即时按下确认 | 进度与阈值 | 完成强调，取消收回 |
| 蓄力 | 准备姿态 | 能量、形变、声音随真实蓄力变化 | 分级释放、中断消散 |
| 拖拽 | 对象抬起 | 落点和合法性持续更新 | 吸附或返回并说明原因 |
| 瞄准 | 准星 | 轨迹、射程、遮挡 | 发射或平稳取消 |
| 拉扯、钓鱼 | 建立接触 | 张力、阻力、危险区间 | 成功释放、断裂、松手 |
| 持续施法 | 连接或范围 | 消耗、接触、状态 | 耗尽、离开范围、主动停止 |
| 生产、建造 | 工作启动 | 阶段、进度、缺料和阻塞 | 完成或中断 |
| 移动 | 启动姿态 | 地面、速度和方向 | 急停、滑停、碰撞 |

连续反馈跟随真实状态。目标离开后光束不能继续表示命中，进度满了不能仍标生产中；取消和中断要有不同含义。

## 反馈语义约定

先定义事实，再选择表现。颜色不是唯一信号，原因靠近原因对象，结果靠近受影响对象；相同语义跨资源和材质保持可辨认。

| 语义 | 含义 | 表现要求 |
| --- | --- | --- |
| 可操作 | 存在合法操作 | 区别于已选中 |
| 已聚焦 | 键盘/手柄输入将作用于此对象 | 稳定焦点，区别于鼠标悬停 |
| 已选中 | 已选择对象或选项 | 直到选择改变 |
| 正在预览 | 尚未执行的可能结果 | 区别于实际变化 |
| 已提交 | 请求已发出 | 避免重复提交 |
| 待确认 | 最终可信结果未知 | 不宣告最终成功或到账 |
| 已接受 | 操作检查通过 | 未必完成 |
| 进行中 | 正在推进 | 进度、状态与阻力 |
| 已完成 | 达到完成条件 | 清除进行中状态 |
| 部分完成 | 部分目标或数量完成 | 成功范围与剩余部分 |
| 被拒绝 | 未通过检查、未开始 | 费用、目标、条件等原因 |
| 主动取消 | 玩家撤回可取消操作 | 平稳退出，区别于失败 |
| 被中断 | 已开始过程被外部打断 | 来源、保留或损失进度 |
| 已失败 | 执行后未达目标 | 实际结果与必要原因 |
| 已过期 | 时间窗口或有效条件结束 | 撤除旧提示 |
| 已命中 | 接触/命中判定成立 | 正确对象、位置与方向 |
| 未命中 | 未接触目标 | 不播放目标受击 |
| 已格挡 | 接触被防御规则阻挡 | 区别于受伤 |
| 已免疫 | 作用发生但效果不适用 | 不表示普通伤害成功 |
| 已就绪 | 从不可用变为可用 | 短提示后回正常状态 |
| 已获得 | 所有权/库存/余额确认增加 | 数量与实际结果一致 |
| 已保存 | 保存确认成功 | 区别于保存中与失败 |

命中不等于造成伤害，接受不等于完成，待确认不等于执行中。稀有度、力度和材质是修饰维度，不替代成功语义。资源不足应强调费用或余额，单独震动全屏不能解释拒绝原因。

| 通道 | 项目内约定 |
| --- | --- |
| 颜色、形状、图标 | 组合表达，同一标记不同时表示成功和危险 |
| 动作 | 选择、确认、拒绝、取消有区别 |
| 声音 | 关键语义稳定，普通脚步/接触可以轻微变奏 |
| 位置 | 来源、原因、目标、结果可对应 |
| 时序 | 预览先于执行，结果跟随确认，结束及时撤除 |
| 强度 | 表达重要性，不改变事件性质 |
| 持续状态 | 有效期间可见，不依赖单次短动画 |

事件上下文应按需包含关联/去重标识、来源与目标、语义、实际数量变化、原因、强度、材质、位置和坐标空间、可见范围、有效期限及生命周期持有者。内部标识不进入玩家界面。

## 组合优先级与预算

优先级由当前玩法决定：致命危险与必须响应的判定最高，当前操作结果其次，重要进展随后，重复装饰最低。经营的生产停摆可能高于一次金币收入；不要写死所有类型的全局排序。

| 重复策略 | 行为 | 典型用途 |
| --- | --- | --- |
| 刷新 | 延长或重启当前反馈 | 持续状态提示 |
| 替换 | 新反馈取代旧反馈 | 最新选择或错误 |
| 有上限叠加 | 增强但限制最大值 | 镜头冲击、能量 |
| 合并 | 多次事件集中表达 | 密集伤害、批量收益 |
| 排队 | 按规则顺序表现 | 联动、奖励；需队列上限与加速策略 |
| 忽略 | 当前期间不重复播放 | 低价值重复提示 |
| 抢占 | 重要事件打断低优先级反馈 | 死亡、危险、退出 |

分别限制粒子、透明覆盖面积、拖尾、飘字、声音、镜头和演出队列；静态烘焙光效与运行附加光效合并考虑。实际阈值、测量方法和触发频率由项目定义，不采用万能数量。

例如一次爆炸击中十个敌人：敌人各有局部反应，伤害飘字可合并，爆炸声音和镜头按爆炸聚合；危险保持清晰，奖励随后展开。不能简单按十次命中触发十次全局冲击。采用独立的表现随机性时，不消耗玩法随机序列而改变掉落或判定；需要回放复现时记录表现种子。

## 声音镜头与环境

声音覆盖起音、持续、结束、材质与力度、距离、递进、音乐阶段和静默。关键危险可压低普通效果，普通音变奏减少重复，语义音保持识别。静音后关键结果仍可见，持续声有明确停止条件。

镜头可用震动表达接触，跟随偏移表达前方空间，缩放表达尺度，移动展示局势。镜头影响全画面，应先考虑局部对象反馈；缩放和回正不能破坏瞄准、距离或阅读。HUD 使用明确的相机分工或独立 UI 场景，设置滚动因子不能单独隔离相机震动、缩放或滤镜。

环境可表达角色呼吸/眨眼/视线，机器运行/满载/损坏，草叶、水面和足迹，开关到电路的传播，修复后灯光恢复或建设后区域活跃。反馈与世界状态有关，装饰不持续争抢主要焦点。

## Cocos 工程边界

先读取目标项目的 `package.json`、Creator 编辑器版本和锁定依赖。以下参考链接指向 Cocos Creator 3.8 文档；其他 3.x 小版本应按项目版本核对 API，不跨版本移植接口。

| 能力 | Cocos Creator 3.x 实现方向 | 边界 |
| --- | --- | --- |
| 形变、位移、透明度 | Creator Tween 系统与职责独立的表现 Node | 保留基准值、属性所有权与取消后的有效终态 |
| 帧动作、特效 | 已验收的 `SpriteFrame`、`AnimationClip` 或项目动画组件 | 规则事件不依赖漏播的一帧结算；播放方式按目标版本及资源合同核对 |
| 接触、尘土、碎屑 | Creator `ParticleSystem2D`、`ParticleSystem` 或项目已有效果池 | 数量、寿命、位置、预算与回收按所用组件实测 |
| 声音 | `AudioSource` 与项目统一音频服务 | 解锁、并发、暂停原因、切场景清理由项目服务管理 |
| 镜头 | Creator `Camera` 配置与项目控制的相机偏移 | 隔离 Canvas UI，声明叠加策略并实测视口与缩放；不假设引擎提供通用震屏行为 |
| 光效与后处理 | 项目实际启用且在目标平台支持的材质/后处理方案 | 不使用未在锁定 Creator 版本核实的滤镜接口 |
| 时间效果 | 游戏规则、Tween、动画、粒子、Spine、声音和输入的分系统协调 | 明确恢复责任、重叠请求、游戏时间与表现时间；不假设存在统一全局倍率 |

Creator Tween 系统可驱动 Node 等对象的变换和颜色属性，并支持延迟、串行及并行动作。Tween 的 `timeScale` 仅在 Creator 3.8.4 及以上文档版本列出，使用前须核对实际小版本，且该设置只作用于对应 Tween；不能把它当作全游戏时间倍率。[Tween 系统文档](https://docs.cocos.com/creator/3.8/manual/en/tween/index.html)、[Tween API](https://docs.cocos.com/creator/3.8/api/en/function/tween)、[Tween 接口版本说明](https://docs.cocos.com/creator/3.8/manual/en/tween/tween-interface.html)。

### 时间控制

| 子系统 | 实施与验证边界 |
| --- | --- |
| 规则、AI、计时器 | 由玩法状态所有者显式处理暂停、顿帧和恢复；修改表现速率不能代替规则冻结 |
| Tween | 逐个确认所属对象、取消方式和恢复责任；需要时间倍率时按目标 Creator 版本核实 Tween 接口 |
| Creator Animation 与帧动画 | 按项目实际动画组件、Animation State 和资源设置管理播放、暂停、切换及收尾；不推断其他子系统随之变速 |
| 粒子与 Spine | 根据具体组件、目标平台和所用数据模式确认更新/暂停策略，不从其他组件的倍率外推 |
| 声音 | 是否续播、暂停或变速是独立选择，遵循项目音频服务及后台恢复合同 |
| 输入与 UI | 明确接受、缓存或拒绝哪些输入，以及哪些界面在时间效果期间继续响应 |

顿帧恢复不能依赖同一顿帧已冻结的计时器。多个请求由具有明确所有权的协调逻辑合并；恢复各子系统此前的有效状态，不把所有系统盲目设为默认值。已有手动暂停、后台暂停或其他时间效果仍需保留，暂停、切场景和对象销毁都必须可靠解除当前请求。

### 渲染、相机与声音

Creator 使用 Scene/Node 层级、`Camera`、Canvas 以及对应渲染组件组织画面。镜头反馈优先使用项目拥有的受控偏移，并为世界内容和 UI 定义清晰的相机边界；连续叠加、刷新、忽略和恢复策略由项目合同决定。需用材质或后处理时，先核对目标 Creator 版本、渲染管线和目标平台的实际支持，不能凭通用滤镜名称推断存在可调用接口。[Camera API](https://docs.cocos.com/creator/3.8/api/en/class/Camera)。

Creator 3.x 的音频播放组件为 `AudioSource`，较长音乐与短音效的实例生命周期由项目音频服务统一管理。Web 播放需遵守浏览器的用户手势策略；场景切换只清理当前所有者的实例，不误停仍有效的全局音乐。[AudioSource 组件参考](https://docs.cocos.com/creator/3.8/manual/en/audio-system/audiosource.html)。

Creator 原生帧动画可由 Animation 系统驱动节点或组件属性；Sprite 帧资源通过 `SpriteFrame` 与项目的 `AnimationClip`/`Animation` 接入。粒子系统按 2D 或 3D 实际组件选择，不能把动画播放、粒子生命周期或音频暂停自动推断为同一个时钟行为。[Animation 系统](https://docs.cocos.com/creator/3.8/manual/en/animation/)、[Sprite 组件](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/editor/sprite.html)、[Particle System](https://docs.cocos.com/creator/3.8/manual/en/particle-system/index.html)。

### 结构与生命周期

| 边界 | 实现要求 |
| --- | --- |
| 业务与表现 | 结算由规则/状态机负责；收集动画取消不丢已确认库存 |
| 物理与显示 | 视觉形变不意外改变碰撞体，真实击退由运动系统负责 |
| 属性所有权 | 移动、受击、待机、布局不无规则地争抢同一属性 |
| 坐标 | 明确世界、容器局部、逻辑 UI、CSS 与物理像素的转换 |
| 基准与偏移 | 基础布局、资源 origin、动效偏移分开，恢复实际基准而非盲设 1 |
| 对象销毁 | 取消附着动作、订阅与迟到回调，独立余波按策略结束 |
| 池化复用 | 重置缩放、透明度、颜色、偏移、动画、监听与关联标识 |
| 场景退出 | 清理当前所有者的反馈和循环声，不误停止全局音乐 |
| 像素风 | 检查采样、旋转、缩放、亚像素与镜头变化引起的闪动 |

先复用现有事件、资源和生命周期模块；需要新增时按职责拆分组件，避免一个管理器接管规则、音频、布局和渲染。不能因一个受击效果就强制引入整套框架。

## 多人和不确定结果

| 阶段 | 允许的反馈 | 必须避免 |
| --- | --- | --- |
| 本地输入 | 按压、操作标记、允许预测的动作 | 未确认就宣告最终到账或胜负 |
| 等待 | 提交/待确认状态 | 重复提交与无限启动动画 |
| 确认 | 实际命中、资源、状态 | 预测和确认重复播放整套效果 |
| 修正/拒绝 | 收回预测、调整、原因 | 成功标记残留 |
| 超时/断线 | 是否可重试、上下文与当前事实 | 让玩家无法知道是否已完成 |

以操作关联标识连接预测与可信确认，定义去重、迟到有效期限和收回策略。移动与购买的预测范围分别决定。隐藏单位、未公开卡牌、对手信息不能被粒子或空间声泄露；观战和回放仍要解释因果，不消耗玩家无法控制的强制演出。

## 完整游戏循环

| 阶段 | 反馈目标 |
| --- | --- |
| 开局 | 出生、目标、控制权交接 |
| 教程 | 学习操作的确认，已掌握后撤去冗余提示 |
| 检查点 | 实际进度已记录 |
| 暂停 | 当前是否推进，焦点与声音状态 |
| 恢复 | 保留上下文，按玩法提供准备时间 |
| 失败 | 来源、后果和可执行下一步 |
| 重试 | 清旧效果、恢复输入与规则，缩短重复演出 |
| 保存 | 保存中、成功和失败按实际结果区分 |
| 胜利/结算 | 核心结果优先，细节随后 |
| 升级/解锁 | 新增能力和查看入口 |
| 再次开局 | 缩短已看说明，保留必要目标 |

失败演出匹配失败成本与重复频率。高难平台更重快速重试，长局策略更重解释后果。存档按钮被点击不能直接表示保存成功。

## 长期体验与可访问性

首次完整说明，偶发保留识别，高频短促局部，批量合并，持续状态不反复播启动，里程碑再强调。检查实际典型单局/连续游玩情境，不规定通用分钟数：声音是否刺耳、震动是否妨碍操作、奖励是否拖慢、界面是否持续跳动、失败是否重复等待、重要事件是否失去区别。

| 设置/限制 | 保留信息的替代 |
| --- | --- |
| 关闭镜头震动 | 局部接触标记或对象反应 |
| 降低闪光 | 轮廓、符号、短暂图标 |
| 减少运动 | 短过渡或静态状态替代大幅飞行 |
| 不依赖颜色 | 形状、位置、图标或文字 |
| 静音 | 可见结果与危险确认 |
| 跳过演出 | 保留结果摘要与必要因果 |

用户设置独立于性能档位。减少效果不能删除必要危险、状态与合法性；省略演出不省略规则结果。触觉只在目标设备能力与任务需要时考虑，不成为通用必需项，也不因此自动真机验证。

| 标准 | 主体与适度环境反馈 | 密集时合并重复 |
| 丰富 | 更多材质、余波和环境细节 | 仍有并发、遮挡和刺激预算 |

降级先处理不可见装饰，再缩短残留、减少透明覆盖和粒子、合并文字与声音、降低背景频率、减少滤镜，最后仍保留关键判定。对象数量不是唯一成本；依据实测帧时间、覆盖面积、内存和并发制定阈值。自动调节要有采样窗口、升降档差异和冷却，避免单帧波动导致反复切档。

| 显示验收 | 用户检查截图/录像并记录实际结果 |
| 手感验收 | 人工操作检查及时、力度、节奏与疲劳 |

### 场景与验证方法

| 场景 | 检查重点 |
| --- | --- |
| 单次正常 | 语义、对象、时序和结果 |
| 高频连续 | 不无限累积、不重复结算 |
| 批量 | 合并数量正确、关键对象可辨 |
| 多事件 | 危险和当前操作不被装饰盖住 |
| 播放中取消/中断 | 正确终态、无成功残留 |
| 立即回收复用 | 新对象不受旧反馈影响 |
| 暂停/后台恢复 | 不永久冻结、不提前结束、不补过期 |
| 镜头和窗口变化 | 世界/UI位置、命中与布局一致 |
| 输入设备切换 | 焦点、选择、提示与触点归属 |
| 静音、减少动态 | 必要信息不缺失 |
| 资源失败、低帧率 | 基础确认与规则正确，降级有效 |
| 网络重复、迟到 | 去重、修正、期限与权限 |

功能和生命周期可以定向自动验证；性能用实测记录；信息清晰度、显示和实际手感由人工检查。截图支持布局、层级和单时刻遮挡，录像/实际操作支持时序、声音同步、恢复与连续体验。不得凭源码、构建、静态通过或一次漂亮演出宣称动态验收通过。

实现任务先推荐 T0-T3 等级、理由、覆盖和实际项目命令，再自动执行适用验证与修复复验；没有通用测试命令可替代项目事实。不自动发起真机，启动服务先查健康可复用实例。只扩展到项目支持的平台、方向和当前受影响状态。

完成标准是当前范围的必要语义、规则结果、重复/中断、资源、预算及适用验收均关闭。缺少人工结果时记录未验证。示例记录可以写“设计已覆盖；仓库满的部分收获规则待确认；程序待验证；显示/手感待人工验收”，不能用一个总 PASS 掩盖不同状态。

## 四类完整设计实例

以下是可转成项目规格的示例，不是可运行实现或已通过的验收；按目标游戏调整参数、阶段和资源。

### 动作：重击命中

| 项目 | 方案 |
| --- | --- |
| 触发/结算 | 规则确认重击；扣血、硬直、实际击退只结算一次 |
| 当下 | 接触火花、目标反应、重击音同步 |
| 时间 | 闪白约 60ms；规则允许时顿帧约 40ms；形变约 140ms 恢复 |
| 粒子 | 可从 8～12 个、200～350ms 试起，沿受击方向 |
| 镜头 | 短促、有上限，危险仍清晰 |
| 重复 | 多目标各局部反应，全局音/镜头/顿帧按攻击聚合 |
| 中断 | 死亡取消姿态恢复，独立碎屑可结束；切场景清理 |
| 降级 | 无震动仍有接触与目标反应 |
| 程序验证 | 不重复扣血，时间可靠恢复，回收后无旧回调 |
| 人工检查 | 命中是否有重量、方向明确、遮挡与重复舒适 |

### 解谜：三消连锁

| 项目 | 方案 |
| --- | --- |
| 触发/结算 | 交换合法且形成匹配；消除、补位与分数由棋盘状态机推进 |
| 交换 | 约 100～140ms，非法返回并指出原因 |
| 消除 | 强调匹配后约 100ms 收缩 |
| 掉落 | 按距离约 120～240ms，轻微落点回弹 |
| 连锁 | 按真实阶段强调与音阶递进，设置上限 |
| 重复 | 同阶段聚合音/分数，不同阶段保留顺序 |
| 中断 | 暂停冻结阶段；跳过表现仍正确推进，不重复计分 |
| 降级 | 保留匹配、连锁次数与棋盘结果 |
| 程序验证 | 无悬空块、遗留动作、重复计分；输入状态正确 |
| 人工检查 | 连锁因果、掉落节奏与视觉焦点清楚 |

### 卡牌：出牌与联动

| 项目 | 方案 |
| --- | --- |
| 触发 | 选择后检查费用和目标，预览不表示实际变化 |
| 预览 | 卡牌抬起、合法目标、费用与预计效果 |
| 结算 | 接受后由规则确定扣费与卡牌去向 |
| 表现 | 约 150～220ms 进入结算位置，按来源→触发者→目标顺序 |
| 拒绝 | 回手牌，指出费用/目标，不播成功 |
| 重复 | 同牌快速点击只提交一次，触发链按实际顺序 |
| 中断 | 跳过交给结算控制器，关闭界面不撤销已确认出牌 |
| 多人 | 本地选择/提交即时，可信结果后确认结算 |
| 程序验证 | 费用一次、目标正确、拒绝无残留、队列可收尾 |
| 人工检查 | 联动来源易辨，加速后仍理解结果 |

### 经营：批量收获

| 项目 | 方案 |
| --- | --- |
| 触发/结算 | 成熟与容量等检查通过，每块地只结算一次 |
| 局部 | 约 100～160ms 弹动后切换正确土地状态 |
| 奖励 | 约 250～400ms 飞向仓库，库存独立于动画完成 |
| 批量 | 合并数量，只显示有限代表图标，限制音频频率 |
| 拒绝/部分 | 未成熟、满仓分别提示；部分收获显示成功和剩余 |
| 中断 | 取消演出不丢已确认收益，切场景库存正确 |
| 离线 | 规则计算后显示汇总，不重播每次收获 |
| 降级 | 保留库存变化和汇总，减少飞行图标 |
| 程序验证 | 不重复入库、数量一致、批量成本受控 |
| 人工检查 | 大量收获仍清楚、节奏舒适、无持续界面跳动 |
