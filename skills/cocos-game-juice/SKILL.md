# Cocos Creator 3.x 游戏汁水感

把当前任务内的玩家操作和规则变化转成及时、可理解、符合主题的反馈。先保证信息和因果清楚，再选择形变、粒子、声音、镜头或时间表现；安静反馈可以成立，不以数量或强度作为质量标准。

可见反馈遵守[游戏内文案](../cocos-game-ui-layout/references/game-copy.md)：奖励、消耗和状态优先用图标、数字、符号或局部变化表达；需要文字时沿用当前可见短标签与显示条件，不把事件规格中的原因、结算规则或设计意图直接做成浮字、Toast 或说明面板。

## 控制面与职责

本领域可提议、审查，并在当前用户任务的 Work Item、Implementation Package 和路径所有权范围内修改反馈设计、配置或实现；结论回到 [cocos-game-workflow-control](../cocos-game-workflow-control/SKILL.md) 审计与状态迁移。不拥有全局状态、审批账本或第二套生命周期，不新增汁水阶段、强制工件或审批门。

Creator Scene/Node/Component、Tween/Animation/ParticleSystem、Prefab、AssetDB 和构建操作必须遵循[Creator MCP 协议](../cocos-game-workflow-control/references/cocos-mcp-protocol.md)并按实时 `tools/list` schema 调用，不手写 `.scene`、`.prefab` 或 `.meta` 绑定。构建面板打开、worker ready 或资源刷新不代表运行通过；无法取得真实 Creator Preview/运行结果时保持 pending/blocked。

- 玩法拥有规则、状态、碰撞和结算；顿帧、击退、吸附、输入缓冲等会改变玩法时，交由玩法及适用的数值领域确定，不能伪装成纯表现改动。
- UI 负责布局、焦点表现与布局坐标合同；玩法保留交互代码，架构维护跨模块坐标约定。反馈通过明确的视觉偏移或表现节点增强，不争抢基础布局属性和输入处理。
- 美术、帧动画和音频继续拥有对应素材生产、登记、时间轴及生命周期。优先复用已有模块，不为调用本 Skill 新建运行时管理器。
- QA 自动核对规则、事件、参数、资源、清理和性能；截图、录像的显示效果及实际手感由用户人工验收。未经明确授权不自动分析画面，也不以机器通过推导视觉通过。
- 沿用已授权的范围、服务复用、当前分支和测试规则；不自动启动真机或执行外部写入、付费、发布等受保护操作。

## 执行闭环

1. 读取当前范围、GDD/brief、实际 Cocos 版本、现有事件和表现组件，确定正在解决的事件、问题与可观察结果。已有反馈契约可复用，不重复创建相同事实。
2. 按类型适用矩阵选择能力，写清准备、发生、结果、持续和收尾中的适用部分，以及成功、拒绝、取消、中断和待确认的语义。
3. 在现有规格中补充事件表；独立反馈任务且原文档不便承载时，可按需使用 `docs/game-feel.md`。记录职责、参数单位、重复策略、时间与坐标空间、资源和清理方式；这是领域事实，不是新机器 Schema。
4. 先确定最小组合，再按重要性增加效果。普通高频事件局部、短促、可合并；危险和当前操作保持清晰。固定数值仅是调参起点，实际阈值由项目定义。
5. 按当前阶段实施或交接：场景设计在 V1 明确意图，V2 纳入既有拆解/布局和生产范围，V3 交付资源，正式场景功能、组合检查和运行验收在既有 V4 范围实现。不得用汁水优化绕过任何有效前置。
6. 按测试等级规则推荐并自动执行适用检查，修复后复验受影响项；提供重复、叠加、中断和收尾的适用动态证据及人工检查要点。未运行、未观看的部分明确标为未验证。

## 交付

只交付当前任务实际需要的事件规格或修订、配置/代码/资源差异、程序与性能证据、人工验收状态及剩余问题。设计完成、实现完成、工程验证和人工体验验收分别记录，不用“有汁水”“很爽”代替证据。沿用既有工件和有效确认，不为本 Skill 重开已完成工作或新增确认链。
