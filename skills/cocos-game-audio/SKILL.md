# Cocos Creator 3.x 音频设计

## 全局控制接入

控制面边界：可提议、可审查、可在当前用户任务的 Work Item 范围内修改，且必须回到 `$cocos-game-workflow-control` 审计和状态迁移；仅涉及外部写入、付费、真机、破坏性或外部删除、发布副作用的 A4-A6 操作请求批准。

本领域可提议、审查，并在当前用户任务、Implementation Package、A 等级与文件范围内修改。所有动作先通过 [`cocos-game-workflow-control`](../cocos-game-workflow-control/SKILL.md) preflight，结果回总控审计与状态迁移；任务内变化同步更新计划，带外部写入、付费、真机、破坏性或外部删除、发布副作用的 A4-A6 操作另行批准。

读取全局 Work Item、项目规格、资源登记和测试计划。按 F0 范围与流程、F1 规格一致性、F2 音频质量、F3 工程验证和 F4 集成/发布决策提交证据；音频方向确认不等于 A4-A6 操作批准。

Creator Scene/Node/Component、`AudioSource`、Prefab、AssetDB 和构建操作必须遵循[Creator MCP 协议](../cocos-game-workflow-control/references/cocos-mcp-protocol.md)，按实时 `tools/list` schema 调用，不手写 `.scene`、`.prefab` 或 `.meta` 绑定。面板打开或 worker ready 不证明预览/构建成功；缺真实运行证据时标记为 pending/blocked。

1. 按核心反馈、UI、环境、音乐和可访问性定义需求。
2. 向美术接入角色提交音频资源登记包，包含来源、授权或生成记录、循环点、格式、时长、响度、用途和发布资格；由美术接入角色串行写入资源登记，避免共享文件并发写入。
3. 设计静音、分组、首次交互播放、暂停恢复和后台切换；基础模块阶段必须实现下述后台暂停与恢复约束，在目标容器和浏览器验证。
4. 依据运行时内存、解码与加载预算，以及渠道真实音频规格选择策略；标记未授权、不可循环、解码或加载峰值过高、或不符合渠道硬限制的资源。
5. 标准、发布通道向总控提交一条音频范围、证据或阻断项，由总控更新控制面；快速通道仅在产生未决决策或阻断项时提交。

向玩法提供触发时机、分组和资源标识，向测试提供功能与预算项，向发布同步授权状态。

汁水感任务可按需参考[动态反馈设计指南](../cocos-game-juice/references/design-guide.md)中的事件语义与声音层次；音频仍独占音频实例生命周期、后台暂停与恢复规则，不由反馈编排另行管理播放实例。

## 后台暂停与恢复约束

- 在基础模块阶段建立统一音频服务与平台生命周期适配，覆盖浏览器页面隐藏/恢复和已采用原生宿主的后台/前台切换；进入后台立即暂停全部正在播放的音乐、音效和语音，后台期间禁止新音频开始播放，不延后到具体场景实现。
- 暂停时保存播放位置及本次由后台切换暂停的实例集合；返回前台后，仅恢复仍有效且没有其他暂停原因的实例，从原位置继续播放，保留循环、音量和静音设置，不从头重播、不重复创建播放实例。原本已手动暂停、已停止、已销毁或所属场景已退出的实例不得自动恢复。
- 页面可见性、原生生命周期和音频中断可能重复或交错通知，统一服务必须合并暂停原因，暂停/恢复保持幂等；只有后台及其他暂停原因全部解除才恢复。后台产生的新播放请求不排队补播，避免返回前台后集中播放过期反馈。
- 浏览器或宿主限制自动恢复时保留待恢复状态，在允许的用户交互或音频恢复事件后继续；不得绕过播放限制，也不得将恢复失败标记为成功。监听器随服务销毁清理，异步恢复完成前再次进入后台时不得产生后台播放。
- 基础实施包和 TDD 记录音频实例所有权、播放位置、暂停原因、生命周期入口与清理策略。验证覆盖播放中切后台后无声、返回后原位置续播、重复切换不叠播、手动暂停不误恢复、后台停止/销毁不复活、后台新请求不补播及恢复受限后的重试。源码检查或构建不能替代实际播放证据；没有运行证据时列为未验证，真机验收不得自动执行。
