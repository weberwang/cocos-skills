# Blender MCP 生产级建模流程

模型几何由 Blender MCP 制作；Cocos Creator 负责真实资源导入核验和工作项要求的运行接入。二者按同一个 Work Item、资源 ID、Implementation Package 和 V0-V4 阶段协作，不增加单独状态机或额外确认阶段。角色边界和交接字段见[模型交接](model-handoff.md)，阶段与登记规则见[工作流接入](workflow-integration.md)。

## 执行前发现

- 检查可复用的 Blender 进程和 MCP 会话，核对 Blender 版本、活动 `.blend`、场景/Collection/对象、未保存更改、外链资源、文件占用和单写者归属；先复用健康实例，不重置或覆盖用户场景。
- 读取当前 MCP 实际暴露的只读检查、网格编辑、修改器、拓扑、UV、LOD、碰撞、保存、导出与回读能力。工具名称、Schema、参数和格式能力以当前发现为准；不得虚构统一命令或把脚本执行能力视为所有建模能力已就绪。
- 若用 Blender Python，先核实对应版本 API、执行上下文、对象选择和模式；在授权脚本范围内逐步执行并读取对象与指标。脚本仅用于获准的 Blender API、数学/网格操作、版本化 `.blend` 保存、模型导出和约定证据输出，不运行 shell、网络、环境变量、凭据、任意文件读取或动态导入。
- 明确资源 ID、来源、可写对象、目标文件和输出根。无法核验归属、保存、导出或回读时，阻断受影响操作，不用 Creator 基础体、外部生成模型或未授权供应商补位。

## 模型规格

在既有 Work Item/模型 brief 中记录：

- 视觉基线及版本、资源 ID、用途、参考来源与许可、目标机位/最近观看距离、识别轮廓与必须建模的结构。
- 世界单位、坐标轴、Pivot、变换、拆件边界、模块接缝、材质槽以及玩法交互体积。
- 顶点/三角面/材质槽预算、法线和切线策略、UV 通道及用途、允许重叠、Texel Density/Padding 的目标和需烘焙内容。
- 适用的 LOD 层级/阈值/轮廓保留要求、碰撞形状和交互要求、角色关节拓扑与变形前置条件（如适用）。
- 版本化 `.blend` 源、实际支持的运行时导出格式、对象命名、输出位置、目标 Creator 项目和技术/视觉证据位置。

生产质量由结构正确性、目标观看条件、可编辑性和运行预算共同决定。低模、模块化或风格化不等于跳过结构、拓扑、法线、主 UV 和导出验证；简单形状也不必为了工艺感添加无关部件。

## 生产工序

| 工序 | 必须完成的工作 | 检查证据 |
| --- | --- | --- |
| 结构分析 | 解析主次形体、连接方式、厚度、开口、材质分区、可动件和玩法体积 | brief 与结构方案覆盖关键外形和交互边界 |
| 比例与轮廓 | 在 Blender 中制作初稿，按固定视角/尺寸参照检查；需要时以 blockout 讨论比例 | 标明中间稿或正式稿；blockout 不计作成品 |
| 正式形体 | 按需求进行硬表面建模、有机建模或两者结合，完成轮廓、厚度、转折、连接和必要倒角；高低模与重拓扑按需采用 | 实际网格表达设计要求；简单形状不堆砌装饰 |
| 拓扑与法线 | 清理重复点、退化/内部废面、意外重叠壳与反面；按需要处理非流形边界；设定硬边、平滑、法线/切线及导出三角化策略 | 记录拓扑检查结果、例外原因、实际面数/顶点数和法线策略 |
| UV 与烘焙交接 | 规划接缝、展开和排布；检查拉伸、越界、重叠、密度与 Padding；区分纹理 UV 和需唯一性的烘焙/光照 UV | 报告实际 UV 通道与岛位置；适用的高低模/Cage/投射信息交由下游 |
| LOD 与碰撞 | 按预算制作适用 LOD，并为玩法需求建立碰撞代理 | 逐级记录面数、轮廓保留、材质槽、阈值及 Collider 类型/数量；不适用项说明原因 |
| 保存与导出 | 保存可编辑源；在派生副本处理应用修改器、变换、法线与三角化；只导出获准对象及必需依赖 | 记录源版本、对象清单、导出参数和真实输出位置；重新导入导出文件检查尺度、朝向、Pivot、网格、UV 和槽位 |
| Cocos 资源核验 | 按实时 Creator MCP Schema 批量导入/刷新并读回 AssetDB 资源、类型、UUID 和实际存在的子资源 | V3 记录资源级结果；V4 记录正式场景实际加载和消费。详细证据边界见[工作流接入](workflow-integration.md) |

高模、重拓扑、额外 UV 集、多个 LOD、高低模烘焙和碰撞代理按资产需求决定；不适用时记明原因，不虚造工件。任何导入格式或引擎侧设置均依据目标 Creator 项目实时可用能力与读回结果，不预设 Unity Importer 或其他引擎设置。

## 成品判定与返修

- 基础几何体可用作起始网格、过程 blockout 或碰撞代理。正式可见网格须完成该资产所需的轮廓、结构、拓扑、法线和 UV 工作；不能仅拼接基础体并赋材质后交付。
- 不强制每个资产雕刻高模、全部四边面或增加细节。方法随形体、变形和烘焙需求选择；若模型设计就是简单几何，按设计和预算完成即可。
- 不用贴图、材质、光照、相机或高面数遮掩几何缺陷，也不把脚本运行成功或导出文件存在当成质量通过。
- 几何、UV、预算、导出回读、Cocos 导入和用户显示检查分别记录。失败时沿用现有 `repair`、`revalidate` 或 `return` 处置；网格、UV、槽位或 LOD 变化后，只重验实际受影响的依赖。
