# 生成式透明能力审计

审计范围：2026-10-09 检查当前可用图像生成接口的参数声明、仓库透明处理代码和输出校验路径。此审计没有调用付费生图服务，也没有取得本轮实际生成文件；真实透明输出能力状态因此保持“未实测”。

| 对象 | 当前可观察事实 | 能证明的内容 | 不能据此证明的内容 |
| --- | --- | --- | --- |
| 当前会话的图像生成接口 | 暴露 `transparent_background` 布尔参数 | 调用方可以请求透明背景输出 | 实际返回 PNG、存在透明像素、保留半透明/辉光/毛发/玻璃边缘，或特定模型版本能稳定交付 |
| `remove-background-local.mjs` | 公共本地工具通过显式 hard-edge 与颜色分离确认执行阈值去背 | 对已确认颜色分离的硬边输入运行可控去背，并输出 PNG、处理记录和预览 | 从复杂背景恢复真实半透明、辉光、柔影、毛发或玻璃，不是通用智能抠图能力 |
| 本地已有 Alpha 复用 | 对输入解码并检查像素后保留现有 Alpha | 可保留已存在的透明像素，适合 provided/reuse 输入 | 不能证明这张图由生图工具生成，也不能补造生成或去背记录 |
| Sharp PNG 元数据 | `metadata().hasAlpha` 反映图像是否包含 Alpha 通道 | 文件声明/编码中存在 Alpha 通道 | 至少一个像素实际小于 255。RGBA PNG 也可能每个像素都完全不透明 |
| 像素级验证 | 必须解码 PNG 的 RGBA 样本并统计 `alpha < 255`、`alpha = 0`、`0 < alpha < 255` 和可见像素 | 输出含真实透明像素，并能检查半透明区域是否仍存在 | 单凭统计不能确认边缘视觉质量；仍须查看浅底、深底预览 |

直接 Alpha 只有在实际工具、版本、输出 PNG 和对应 `edge_profile` 都有可复核证据时才能登记为已验证能力。generation record 顶层以 `generator/generator_version` 记录实际生成身份，嵌套 `capability.tool/tool_version` 是该身份的能力证明字段，必须与生成身份一致。证据至少绑定原始输出路径、解码后的 Alpha 像素统计、请求参数和同一候选的浅底/深底预览；每种边缘类型分别验证，不能从硬边测试推导玻璃或辉光能力。工具参数、提示词、`.png` 后缀、RGBA 通道或工具文档中的能力声明都不能替代像素证据。

可确认的格式边界：JPEG 不保留 Alpha；PNG 可以有 Alpha 通道但全部像素仍保持不透明。归一化应从真实解码的 Alpha 数据检查输入和输出，保持非等比之外的原画比例、主体可见边界和半透明像素；存在真实透明像素时最终文件必须是 PNG。棋盘格是展示背景，若像素中出现棋盘图案，它就是不透明图像内容，不能当作 Alpha。

后续能力更新必须补充真实工具调用与版本、固定输入条件、实际原始输出、PNG 解码结果、两种底色预览以及人工检查结论。没有这些材料的工具和边缘类型保持未验证；遇到复杂边缘时应明确报告缺口，并按冻结合同选择遮罩/人工创作、重新生成或经变更批准的 Cocos 特效。
