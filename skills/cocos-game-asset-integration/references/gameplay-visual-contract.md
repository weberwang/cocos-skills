# 玩法视觉契约

## 目的

把“好看”转换成玩家在运动和压力下可识别、可预判、可操作的约束。每个关键玩法状态都要填写契约；静态效果图、像素接近、资源齐全或单次截图不能证明游戏性。视觉验证默认使用 `visual_validation.mode=usability`，优先判断可识别、可预判、可操作和明显遮挡/越界问题；只有明确精确需求时才使用 `exact`。

主题、受众、体验目标、三层刺激预算及人工质量边界统一读取[游戏美术体验与质量契约](art-quality-contract.md)。玩法可读性、静态舒适度和持续游玩体验分别提供证据，不把更强光效或更多装饰作为玩法反馈的默认要求。

场景、整套 UI、视觉系统和参考还原还必须冻结 [`cocos-game-ui-layout` 的布局合同](../../cocos-game-ui-layout/references/layout-contract.md)。
其中四层坐标、适配策略、背景覆盖、留白/裁切/拉伸许可、代表性视口和动态 resize 是
响应式唯一详细规范；QA 的[响应式视觉验证](../../cocos-game-qa-performance/references/responsive-visual-validation.md)
负责测量和证据格式。原子资源只有在已有有效契约与预算基线时可引用，否则按影响升级。

## 逐状态契约

| 字段 | 要求 |
| --- | --- |
| 第一视觉目标 | 玩家进入状态后最先必须看见并理解的对象或变化，只写一个主目标 |
| 玩家与体验 | 引用当前 brief 的主题、目标受众与体验目标，说明本状态如何支持核心循环 |
| 视觉优先级 | 按玩家、目标、危险、交互、装饰排序；同级冲突写出化解方式 |
| 明度/色彩 | 定义前景背景对比、状态色与灰阶仍可识别的辅助信号 |
| 轮廓/尺度 | 定义小屏和高速运动时仍稳定的外轮廓、最小占屏和安全留白 |
| 运动区分 | 定义方向、速度、节奏或轨迹差异，避免只靠颜色表达 |
| 可供性（affordance） | 明确可点击、可拖动、可拾取、可伤害、可阻挡等可供性及反馈 |
| 反馈时序 | 定义前摇、命中、受击、奖励出现、峰值、保持和收尾时长 |
| 遮挡预算 | 定义关键目标最大遮挡比例、遮挡持续时间和同屏特效上限 |
| 刺激层级 | 标明常态、操作反馈或事件峰值；强度对应玩法重要性，静态高光与运行附加特效合并计入预算 |
| 重复与叠加 | 定义实际触发频率、并发上限、去重/合并/冷却策略、混合方式及恢复常态的条件 |
| 持续观看 | 按典型单局/连续游玩情境定义复验片段、持续注视区域与人工检查要点 |
| 差异条件 | 覆盖小屏、高速运动、灰阶和项目要求的色觉差异模式 |
| 量化阈值 | 由项目定义对比度、最小像素/角尺寸、响应延迟、持续时间、遮挡比例、同时出现数量等阈值 |

没有通用数值时，适用 V1 的路径标记“项目待定义”，由项目负责人和测试共同冻结；原子资源只有在既有基线已经给出适用有效阈值时才可走轻量路径。不得假装存在行业默认值。

## V1 低保真证据与确认

适用 V1 的路径必须用低保真草图或灰盒证明结构、状态、交互和布局。需求与基线明确时记录 `AUTO`，直接给出场景目标/宿主上下文预览；不要先提交文字判断等待确认。Work Item 指定效果图忠实还原时，默认 `usability` 允许小幅位置、尺寸、边距和换行差异；只有改变产品方向、玩法语义、上游结构或正式目标，或明确要求 `exact`，才询问并记录 `USER_DECISION`。问题可通过图像表达时优先展示图片选项。专业修复不得静默改变玩法规则；任何决定都不能替代 V2 拆解图确认、布局图确认及其机器证据。

自动路径和用户决定都由代理记录在权威工件中：前者记 `AUTO` 依据并继续预览，后者只用于实质取舍；用户无需另行确认记录文本。修改后重跑 F0-F3 并重新分类，仍有实质取舍则保持 `USER_INPUT_REQUIRED`，不得准备操作审批 pending。

## 动态可玩样片

V2 以最小可玩切片验证契约，至少包含正常操作、错误/受击、奖励/成功、遮挡峰值和性能压力中的适用项；默认响应式路径覆盖基准及代表性窄/宽、项目支持方向和关键状态，验证动态文本、成员显隐、滚动、触控、重锚定和 resize。单方向项目只测支持方向内的视口尺寸；仅双方向项目要求横竖屏切换。只有 `exact` 或明确全覆盖需求时才执行基准、最窄、最宽、支持方向和安全区完整矩阵。只有基准静态图阻断 V3。证据可以是录屏加输入日志，或能复现相同状态、随机种子、视口、输入与时间点的自动轨迹。

对每条轨迹记录：构建版本、设备/视口、设备像素比、输入序列、随机种子、状态起点、关键时间采样、稳定帧规则、预期第一视觉目标、观察结果和失败回退阶段。

## V4 验收

- 第一视觉目标在目标设备、小屏缩小和高速运动中仍可识别。
- 危险前摇早于伤害，命中/受击/奖励反馈顺序与持续时间符合契约。
- 颜色不是唯一信号；灰阶和目标色觉差异条件仍能区分关键状态。
- 装饰、VFX、字幕和 UI 不超过遮挡预算，不抢占玩家、目标、危险与交互层级。
- 正常游玩和高频重复反馈分别符合对应刺激层级；同屏叠加不累积变亮，事件峰值及时收尾并恢复常态。
- 按 brief 的持续观看情境提交实际动态片段，由用户确认焦点、反馈干扰、观看舒适与主题/受众适配；只有静态截图或单次效果时，持续游玩结果保持未验证。
- 正式资源没有破坏 V1 `AUTO` 或 `USER_DECISION` 覆盖的结构，且 V2 拆解图确认与当前决策记录绑定的动态表现有效。
- 运行态默认使用代表性 viewport 截图和同页面 resize 轨迹；Canvas ROI、逻辑画布或背景不溢出只能作为补充。只有 `exact` 或明确要求时才要求完整 viewport 与严格差异证据；默认重点检查可读性、边界、遮挡和交互。

任一项失败按根因返回 V4、V3、V2 或 V1；不以补一张静态截图关闭问题。

参数、事件轨迹和预算可以自动验证；视觉显示效果由用户人工检查，未明确授权自动视觉验证时代理不分析截图/视频画面。沿用现有验收材料和确认节点，不恢复旧 `human_review` 字段或增设逐资源确认。
