# 游戏美术体验与质量契约

本契约用于全局视觉 brief、场景效果图、正式资源和动态运行验收。目标是让美术支持玩法、项目主题与目标玩家，并适合项目约定的持续游玩情境。它补充现有 V0、V1、V2、V3、V4 领域质量要求，不新增状态、审批阶段或逐资产确认链。纯工程任务不适用；原子资源可继承当前有效基线，只重验受影响部分。

## 设计依据与适用边界

- [MDA 原论文](https://users.cs.northwestern.edu/~hunicke/MDA.pdf)：先确定玩家期望的感官、幻想、挑战或探索等体验，再说明视觉与反馈如何支持核心循环。这里的美学指玩家情绪体验，不等于图像精细程度。
- [Riot 游戏清晰度原则](https://www.leagueoflegends.com/en-us/news/dev/clarity-in-league/)：视觉表现吸引的注意力应对应玩法重要性，并控制同屏视觉噪声。普通操作不能与关键危险或重大事件争夺同等注意力。
- [Valve 美术指南](https://help.steampowered.com/en/faqs/view/0688-7692-4D5A-1935)：选择性分配明度、饱和度与细节，用较简单的区域平衡复杂区域，并在实际游戏视角与背景中评价作品。
- [Xbox 视觉干扰与运动设置指南](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117)：检查非必要闪烁、自动运动和镜头运动；在适用玩法中提供减少或关闭干扰的设置。

上述原则是决策依据，不提供统一亮度、饱和度、频率或游玩时长阈值。项目自行定义预算、测量口径和观看情境，不将其表述为医学安全标准。科幻、霓虹、卡通、扁平或高饱和风格均可按主题采用；问题是注意力分配、表现完成度和实际观看效果，而不是某种风格名称。

## 项目美术 brief

全局三候选生产前建立结构化 brief，完整字段以控制面的美术 brief Schema 为准；以下事实必须进入实际生成输入，并在冻结基线正文中形成可执行的规则：

| 内容 | 必须说明的事实 |
| --- | --- |
| 项目主题 | 世界、文化/时代线索、角色与道具语义；读取当前 GDD，不能沿用其他项目的固定角色或题材 |
| 目标受众 | 玩家偏好、游戏经验、主要使用情境与依据；区分用户已确认事实和待验证假设，不凭年龄标签推断审美 |
| 核心循环 | 玩家持续观察、选择和操作什么，美术如何帮助识别、预判与反馈 |
| 体验目标 | 期望的情绪及优先级，例如轻松解谜、探索好奇或战斗张力；不能只写“高级、精美、震撼” |
| 观看情境 | 主要设备、目标逻辑显示尺寸、典型单局/连续游玩情境、持续注视区域和复验片段 |
| 视觉层级 | 核心对象、危险、操作反馈、HUD 与背景的注意力顺序；保留可解释的视觉休息区 |
| 刺激预算 | 常态、操作反馈、事件峰值各自的亮度/对比、占屏、时长、频率、叠加和收尾规则，以及测量口径 |

brief 中的主题、核心循环、体验目标和预算是内部生成依据，不是要绘制的文字。实际生成输入还须引用现有 GDD/场景规格中的[玩家可见表达](../../cocos-game-ui-layout/references/game-copy.md#工作流接入)，列明图标/图片、示例数值、必要短标签与显示条件，并发送[效果图文案约束](../../cocos-game-ui-layout/references/game-copy.md#效果图生成)。不为此增加 brief Schema 字段，也不把内部说明混入可见文字列表。

正向参考说明要继承的造型、材质、光影与层级；失败反例说明刺眼、廉价、拥挤或偏离主题的具体原因。没有现成反例时如实记录，不为凑材料生图。受众适配假设在后续目标玩家反馈中验证，不把作者或代理喜好当成事实。

## 常态与事件强度

| 层级 | 用途 | 约束 |
| --- | --- | --- |
| 常态 | 背景、常驻 HUD、普通角色/棋盘、空闲循环 | 保持稳定层级与可读性；高光有材质依据，装饰不持续抢焦点；细节密集区有安静区域平衡 |
| 操作反馈 | 点击、移动、匹配、普通命中、拾取 | 与具体操作及时对应、容易分辨且及时结束；高频触发须规定合并、去重、冷却或数量上限，不能无限叠加 |
| 事件峰值 | 关键危险、重大胜负、稀有奖励或阶段达成 | 强度对应事件重要性；规定峰值范围、保持与衰减，结束后回到常态；不要求所有玩法都有爆闪或大面积光效 |

预算逐项考虑亮度/对比、面积、持续时间、单位时间触发次数、同时出现数量与混合方式。分别记录素材内烘焙光效和运行时附加光效，检查相加后是否超预算；常态不能通过自动曝光或持续叠加逐渐变亮。关键对象的可读性不能靠整体压暗或降低所有颜色饱和度换取。

反馈完成度按玩法意义判断。安静的形变、姿态、声音、数值或局部状态变化在目标尺寸下足以表达事件时，可以成立；不能为通过“游戏感”检查强制添加粒子、镜头震动、闪屏或购买庆祝。非必要运动/光效的减弱设置不能取消必要危险与状态信号。

## 五项质量与候选淘汰

全局三候选仍同条件生产、同屏交给用户，逐候选记录下列五项的人工结果与具体原因。每项只能为通过、失败或未验证，不能用总分平均抵消失败：

| 质量项 | 人工检查重点 |
| --- | --- |
| 主题贴合 | 造型、角色、道具与世界线索是否支持当前项目主题，是否存在无依据的通用装饰 |
| 受众适配 | 是否符合已声明偏好、游戏经验和使用情境；尚无依据的推断是否明确标记 |
| 玩法可读 | 实际目标尺寸下能否识别对象、危险、操作与状态，装饰是否抢占焦点；图标/数值归属清楚，无规格说明或重复解释，必要条件与后果完整 |
| 观看舒适 | 常态高光、饱和色、对比、细节和留白是否平衡，是否存在持续抢眼或刺眼区域 |
| 美术完成度 | 轮廓、比例、透视、材质、高光依据、光源、字体/图标与边缘质量是否协调，有无明显生成瑕疵 |

所选候选必须五项均通过，人工偏好选择不能覆盖失败或未验证项。三张全部不合格时保留失败原因，修正当前 brief/生成方案后生产新的同条件三候选批次；在出现合格候选且人工确认前保持 draft/pending，不冻结“相对最好的一张”。机器只核对三候选与评估结果的身份、覆盖、状态和实际文件，不据此声称理解了作品质量。

全局候选只验证该静态候选能观察到的质量；静态“观看舒适”通过不代表持续游玩通过。场景 reference target 和显示层上下文效果图在冻结前按同一五项复核，并将结论纳入现有方向/拆解材料与用户确认。不要增加另一套审批账本、旧 `human_review` 字段或逐部件复核身份。

## 生成与忠实还原

生成包除既有全局风格、资产和状态事实外，必须发送与当前资产相关的受众、体验目标、视觉层级和强度预算；负向约束对应具体失败模式，例如“普通按钮没有常驻外发光”“布料不呈现塑料镜面高光”。只保存实际发送的内容，不在生成后补造提示词。

冻结前解决刺眼、质感和主题问题；冻结后的 effect-image 拆件仍忠实还原。若目标本身不符合质量要求，列出冲突和影响，修改受影响上游目标并重新确认，不在拆件或运行时暗中换风格、删光效或降低验收标准。素材瑕疵或运行叠加问题在当前生产/运行阶段修复；只有上游事实真实改变才回到最早受影响阶段。

## 持续游玩验收

V4 在正式场景中检查正式素材同屏后的层级与质感，并按 brief 约定的典型单局或连续游玩情境准备可复现片段，覆盖当前玩法适用的正常操作、高频重复、危险/错误、奖励峰值和同屏叠加。复验长度由实际玩法节奏决定，不指定通用分钟数；不自动发起真机验收。

每段绑定候选、场景/状态、基线版本、视口、输入或随机种子、开始/结束时间、事件次数、峰值并发和预算实测。截图只能支持静态事实，不能替代连续动态片段；不能以单次最漂亮的奖励动画代表正常游玩。

代理生成并提供截图/录屏、参数测量和检查要点，视觉显示效果由用户人工检查并确认。用户未明确要求自动视觉验证时，代理不得自动分析截图或视频画面、给舒适度评分或宣称视觉通过；自动化仅核对结构、实际参数、文件与证据绑定。若明确授权自动视觉检查，也不能冒充全局选图或现有阶段所需的人工确认。

人工记录沿用 `docs/visual-design.md`、当前任务验收材料及现有确认节点，至少包含：片段身份与时间范围、主要观察区域、持续抢眼/疲劳感、关键对象辨识、重复反馈是否干扰、叠加/收尾、主题/受众适配、结果及返工意见。V4 的实际运行候选文件内保存 `artExperienceAcceptance`，按[运行美术验收 Schema](../../cocos-game-workflow-control/references/art-experience-acceptance.schema.json)绑定当前 work item、candidate、场景上下文、五项人工结果、观看情境、确认时间与用户原文。完成门读取该真实材料，缺失、失败或未验证均阻断；机器仍只核对记录与文件，不判断画面。

动态情境按 `normal-play`、`repeated-feedback`、`event-peak`、`overlap-peak` 唯一登记。正常使用片段必需，静态场景可以是实际常驻/浏览情境，不强制创造玩法；其他情境按实际功能声明 required 或 not-applicable 并说明理由。required 绑定仓库内真实录屏文件、有效起止秒数、触发次数、峰值并发和实际人工观察；不适用项不伪造录屏、时段或计数。尚未完成持续观看检查时明确写“未验证”，不能把静态候选结论直接带入 V4 完成结论。已经确认且内容未变化的部分不重复询问。

功能可用、参考还原一致与美术质量分别记录，全部适用要求满足后才交付。美术不能单独证明玩家会继续玩；核心循环、难度与节奏问题交回玩法/数值工作项，目标玩家的继续游玩意愿作为体验反馈，不包装成美术质量的确定性保证。
