# 游戏感质量硬门

全局视觉基线的候选、人工选择和冻结状态以[全局视觉控制](global-visual-control.md)及控制面 Schema 为准。本文件只定义游戏感领域质量事实；V2 仍按控制面先完成拆解确认、再完成布局确认，实质取舍记录 `AUTO` 或 `USER_DECISION`。

本门禁拦截“文件与工程证据充分，但画面仍像后台、表单、工具应用、PPT 或网页模板”的候选物。默认 `visual_validation.mode=usability`，关注玩家能否识别、预判和操作；不得用清晰度、圆角、阴影、渐变、插画数量、构建通过或主观声明代替游戏感证据。只有明确 `exact` 需求时才增加像素级或全矩阵比较。

游戏感必须同时符合[游戏美术体验与质量契约](art-quality-contract.md)的主题、受众、可读性、观看舒适与完成度要求。判断依据来自当前项目 brief，不把更亮、更复杂或更强烈的反馈当作统一质量标准。

需要具体的动态反馈语义、类型适用矩阵或事件覆盖核对时，按需参考[Cocos 2D 汁水感设计指南](../../cocos-game-juice/references/design-guide.md)。该指南补充设计依据，不改变本文件的评分尺度、质量硬门或人工验收边界。

## 门禁原则

1. 每个核心项同时引用候选版本、候选截图/片段、具体区域或时间范围及实际人工观察。只写“有游戏感”“风格统一”“构图无问题”等结论视为缺证。
2. 任一核心项缺证、明显失败或只有主观声明时，当前阶段的游戏感 F2 不通过，候选不得进入后续阶段。
3. 区分领域质量与工程验证：游戏感质量说明画面是否支持玩家幻想、核心玩具、行动召唤和反馈；文件、资源、运行态和响应式证据由 V3/V4 领域合同验证。
4. 机器核对合同、资源、参数与证据绑定，用户人工判断画面的游戏感、主题、质感及舒适度。未明确授权自动视觉验证时，代理只提供截图/录屏和检查要点，不自动分析画面或填写通过；人工意见沿用现有确认与验收材料，不恢复旧 `human_review` 字段。总控核对流程和证据，机器 PASS 不能推导美术通过。

## V1 与 V2 的结构边界

V1 冻结功能、状态、交互与页面几何。必要灰盒和证据关闭后，明确需求/参考路径写 `AUTO` 决策进入 V2；仅实质结构取舍请求确认。

忠实还原模式下，效果图提供视觉事实和结构参照，游戏感审查用于发现与说明问题。不得以“更美观”“提升游戏感”或“专业修复”为理由静默改动产品方向、玩法语义或上游结构；默认 `usability` 允许不影响可用性的小幅位置、尺寸、边距和换行差异。若游戏感要求与上游视觉事实冲突，结构修订包必须列出影响与候选方案并形成一次 `USER_DECISION`；细节偏差不自动升级为决定门。

V2 或对应 F2 发现下列任一结构无法支持游戏感时，提交“结构修订包”并退回 V1：

- 构图把核心玩具、角色或主要行动压成次要信息；
- 信息层级无法形成第一视觉焦点或清晰行动召唤；
- 资源槽不足以承载角色、奖励、反馈、专属场景对象或状态变体；
- 页面模板迫使多个页面重复同一容器和内容节奏；
- 几何、响应式或安全区约束导致核心对象失去舞台感、反馈空间或可读性。

结构修订包必须包含失败事实、重审范围、不变语义与验收条件。旧决策记录失效或缩小范围，新候选重新执行条件分类并记录 `AUTO` 或 `USER_DECISION`。

参考还原在参考证据足以证明结构时保持参考结构。重新设计、重做或提升游戏感时，必须允许视觉方向推动 V1 几何重审；低保真 `USER_DECISION` 不得阻止专业回退或豁免结构缺陷，禁止用“V1 已记录”强迫后续实现继续套用不支持游戏感的灰盒结构。

## V2 领域质量检查

V2 的游戏感检查只补充当前拆解和布局方案的领域事实：核心玩具、第一视觉焦点、行动召唤、状态反馈、适用的奖励期待、页面差异、沉浸完整性及静态美术质量必须有可观察证据。静态舒适度不代表持续游玩通过；动态刺激与重复反馈在 V4 验收。拆解确认和布局确认是两个独立的用户确认门，分别由对应合同记录；本文件不新增方向候选或额外确认门。

自动路径记录 `AUTO`；需要用户选择时记录 `USER_DECISION` 结论并回写权威工件。修改后按控制面重跑受影响的 F0-F3；实质取舍仍未解决时保持 `USER_INPUT_REQUIRED`，不得准备操作审批 pending。

## 核心审核项与评分

适用项由用户按下列尺度评分，并保留实际意见来源与证据引用；不适用项写明玩法依据，不为凑全模板新增页面、奖励或特效：

- `2`：候选截图中有明确、稳定、可观察的视觉事实，能够支持该项；
- `1`：部分满足，覆盖不全或存在可读性、舒适度、完成度或主题冲突，结论失败，修复后重验受影响事实；
- `0`：缺证、明显失败，或只有主观声明。

任一适用核心项为 `0` 或 `1` 时，美术领域结论只能是失败或未验证，修复后在实际新候选上重验受影响的机器事实与人工画面。评分不写入 `validationMode=MACHINE` 的机器结果；机器出口和美术验收分别记录，任一未满足都不能声明交付完成。不得用总分平均掩盖单项失败。

### 1. 玩家幻想与世界身份

- 指出玩家扮演、照料、收集、挑战或推进的幻想，并标注承载该幻想的角色、场景、道具或空间。
- 根据当前 GDD/brief 的项目主题，检查角色、造型语言、场景道具与叙事线索能否表达世界身份；不能把其他项目的固定角色或题材写进通用门。需要文字表达玩法语义的项目保留必要文字，不能强制依赖装饰代替规则。

### 2. 核心玩具感与第一焦点

- 标注第一视觉焦点，说明核心可玩对象为何像可触摸、可操控、可获得反馈的游戏玩具，而不是数据展示组件。
- 检查体积、层级、尺度、材质、状态空间和交互暗示；核心玩法若被导航、表格、说明或装饰压制则不通过。

### 3. 行动召唤与主要交互

- 标出主要行动入口，证明玩家无需阅读说明即可判断下一步。
- 用位置、尺度、对比、形状、姿态、光效或动势建立行动召唤；不得只依赖灰色按钮文字或网页式链接。
- 按[游戏内文案](../../cocos-game-ui-layout/references/game-copy.md)检查图标与数字能否直接表达奖励、消耗、倍率和进度，是否仍附带重复标签或解释句，以及多个通用图标是否堆叠成工具栏式界面。移除重复说明后仍须看懂功能与数值归属；歧义图标、首次必要引导、操作后果保留最少说明，无障碍名称可不进入可见布局。

### 4. 状态反馈强度

- 分别提供选中、错误、提示、购买、成功和失败的关键截图或状态分镜。
- 证明适用状态在目标尺寸和实际节奏下可分辨、语义明确，强度对应玩法重要性。文字、数值、图标、姿态、形变、声音或局部光色均可按项目体验目标表达；信号不足才返工，不因反馈安静就判定失败，也不强制增加粒子、闪屏或镜头震动。

### 5. 奖励期待与情绪峰值

- 标注奖励预告、稀有度、进度临界点、开启/领取动作和结果展示如何制造期待。
- 按项目体验目标说明哪些重要事件需要情绪峰值、采用何种表现及如何收尾；普通高频收益与购买不自动升级为庆祝。安静玩法可通过局部变化或完成仪式表达满足感，不强制爆闪或大面积发光。

### 6. 视觉语言一致性

- 对照冻结基线的风格指纹、主锚点和分系统锚点检查角色、图标、面板、按钮、光源、材质、描边和色彩，引用具体区域说明它们共享的造型与渲染规则。
- 任何主要系统出现互不相容的扁平线框、写实材质、塑料高光、纸张纹理、描边粗细、光源方向或色彩逻辑时，判定材质体系割裂。
- 不得用“同一关键词”“同一模型”“同一调色板”或作者声明代替多资源联系表、同屏截图和可观察事实。

### 7. 页面场景差异

对项目实际存在的页面，证明其在全局不变量内具有相应场景身份、核心对象和内容节奏。以下是适用时的用途示例，不要求创建列表中的全部页面；场景差异不得退化为同一模板，也不得变成不同美术体系：

- 主页承担世界入口与主行动；
- 关卡突出核心玩具、即时反馈和胜负张力；
- 藏品具有可收集、陈列或成长的专属视觉对象；
- 签到具有日历、连续轨迹、宝箱或领取仪式等专属对象；
- 排行榜具有名次、对手、领奖台或竞争进度等专属对象；
- 锦标赛具有赛制、对阵、奖杯、赛场或阶段晋级等专属对象；
- 挑战具有目标、限制、风险、倒计时或特殊奖励等专属对象。

六个或更多页面复用“标题 + 白卡片 + 灰按钮”模板，或藏品/签到/排行榜/锦标赛缺少专属视觉对象时不通过。

### 8. 沉浸完整性

- 检查所有可见文案、角标、标签、日志区和占位区域。
- 候选画面不得出现“未实现”“本地演示”“操作未启用”、stable ID、调试说明、开发状态、测试口径、资源键、组件名或面向开发者的限制说明。
- 必需的不可用状态必须改写为世界内、玩家可理解的反馈，并以游戏内视觉状态表达原因和下一步。

### 9. 受众适配、观看舒适与完成度

- 将当前受众与体验目标关联到实际画面，区分已确认偏好与待验证假设，不用作者喜好或年龄刻板印象作结论。
- 按五项质量检查轮廓、比例、透视、材质高光、光源、色彩/细节分布与边缘瑕疵；塑料材质可以有相应高光，布料或纸张不能无依据地套用镜面质感。
- 常态保留清晰层级与视觉休息区；高频操作和重大事件分别遵守刺激预算。V4 由用户查看正常游玩、重复触发、叠加和收尾的适用动态片段，未观看时保持未验证。

## 自动退回规则

发现下列问题时默认至少登记 P1/P2 并退回 V2；根因属于信息结构、布局几何、资源槽或页面模板时提交结构修订包并退回 V1：

- 整体呈现后台、表单、工具应用、PPT 或网页模板感；
- 存在无职责的大空白，不能解释为焦点留白、动效空间、场景纵深或安全区；
- 六页面或更多页面重复“标题 + 白卡片 + 灰按钮”；
- 主要识别元素由通用线性工具图标承担；
- 角色、图标、面板、按钮、光源或材质体系割裂；
- 状态无法辨识，或高频反馈与关键事件争夺注意力、叠加高亮不收尾；
- 藏品、签到、排行榜、锦标赛或其他玩法页缺少专属视觉对象；
- 所谓高保真只是给灰盒增加圆角、阴影、渐变和插画；
- F2 只写“构图无问题”“风格无问题”等结论，没有截图、区域和事实。
- 人工评估发现刺眼、材质失真、明显生成瑕疵、主题/受众偏离，或持续游玩舒适度失败。

机器确定的合同/参数缺陷和用户实际指出的美术缺陷都必须修复，不能提交 F4 请求豁免。视觉审美与舒适度不能宣称由确定性机器规则裁决；人工选择也不能覆盖已失败的质量项。V1/V2 的 `USER_DECISION` 不替代当前机器 F2 事实，机器事实不替代实际人工画面验收。

出现全局规则或方向漂移时退 V2；基线绑定、生产规格或生成包缺失时退 V3；正式资源执行偏差退 V4；构图、信息层级、资源槽、页面模板或布局结构根因退 V1。冻结基线变更必须提交影响面并重验受影响锚点、资源、状态、页面和运行证据。
