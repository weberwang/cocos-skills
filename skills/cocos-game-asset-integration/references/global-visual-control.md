# 全局视觉控制约束

为每个项目维护单一、版本化的全局视觉基线。候选选择、冻结状态和跨 Work Item 引用以[控制模型](../../cocos-game-workflow-control/references/control-model.md)及对应 Schema 为准；本文件只补充全局视觉基线的锚点、风格和生成记录要求。`docs/global-visual-baseline-selection.json` 是唯一选择根证据模板；`docs/visual-baseline.md` 只保存不可变冻结规则正文，`docs/visual-design.md` 保存可追加的方向探索、版本索引及 V2/V3/V4 证据，`docs/visual-assets.json` 只保存机器绑定与选择证据索引；选择根证据单独保存，不在其中内嵌第二份根对象。

## 生产者与消费者绑定

选择根证据的顶层 `workItemId` 永久表示创建三候选和人工决定的生产者 Work Item。三张候选的 generation record、唯一人工决定文件和根证据必须继续绑定同一生产者，不能因为场景 Work Item 消费该基线而改写这些文件的所有者。消费者只保存 `globalVisualBaselineSelectionRef` 的不可变 `path`；引用中的可选 `workItemId` 也只能复述生产者身份，不能填写或要求等于当前消费者 Work Item。这样同一冻结根证据可以被多个场景、显示层或基础模块 Work Item 复用，同时仍由文件门校验生产者链和每个实际文件。

## 基线身份与风格指纹

冻结基线时同时记录：

- 基线 ID、语义化版本、状态、冻结日期和负责人；
- 风格指纹：可选追踪记录，不检查格式或与文件比对；实际基线 ID、版本和视觉内容仍需满足要求；
- 主锚点：最能代表项目世界幻想、渲染方式、情绪和质量密度的同条件截图或动态片段；
- 分系统锚点：角色、场景、UI、图标、动画、VFX、字体等系统各自的代表画面；
- 基线文档、锚点证据、适用范围、允许变量和已知边界。

基线 ID 表达视觉系统身份，版本表达已批准规则集合，风格指纹只计算 `docs/visual-baseline.md` 完整文件字节。不得把摘要或 V2/V3/V4 留痕写回被哈希正文；阶段证据追加到 `visual-design.md`。规则实际变化时更新版本并重验受影响部分；摘要变化不影响验收。`--check-files` 重新计算冻结正文 SHA-256。

## 三候选生成与人工冻结门

全局视觉基线必须从[游戏美术体验与质量契约](art-quality-contract.md)规定的结构化视觉 brief 开始。`brief.path` 指向符合 [`game-art-brief.schema.json`](../../cocos-game-workflow-control/references/game-art-brief.schema.json) 的 JSON 实际文件，记录生产者 Work Item、brief ID、主题、受众、核心循环、体验目标、观看情境、视觉层级和三层刺激预算。字段齐全不能证明方向合理；用户未确认的受众偏好明确写为待验证假设。

使用相同 brief、目标视口、参考输入和实际生成条件生成恰好三张候选效果图，并将三张图同屏交给人工比较；候选必须关联实际图片和 generated generation record 文件，不要求摘要。`global-visual-baseline-selection/1.1` 证据还必须绑定生产者 Work Item、brief、generation batch、唯一候选 ID、唯一 `SINGLE_HUMAN`/`CONFIRMED` 选择、selectedCandidateId、决定记录文件、确认时间和用户原文。候选生成记录仍使用 `global-visual-baseline-candidate-generation/1.0`；决定文件使用 `global-visual-baseline-selection-decision/1.1`。

三候选使用相同的玩家可见表达与示例数值，实际提示词按[效果图文案约束](../../cocos-game-ui-layout/references/game-copy.md#效果图生成)分离内部 brief 与可见文字。不得将核心循环、玩法介绍或验收说明当作界面文字绘制；该检查纳入下述玩法可读人工评估，未完成时不声称画面通过。

人工选择同时完成逐候选五项检查：主题贴合 `themeFit`、受众适配 `audienceFit`、玩法可读 `readability`、静态观看舒适 `comfort`、美术完成度 `craft`。`humanSelection.candidateAssessments` 与决定文件保存同一份按 candidateId 绑定的实际人工结果；每项填写 `status=passed|failed|unverified` 与具体 `reason`。所选候选五项必须均为 passed，不能用平均分或用户偏好抵消失败。三张都不合格时保留失败材料、修正生成方案并重新生产三候选，保持 draft/pending；没有合格且经人工选择的候选不能冻结。代理只提供图片和检查要点，不自动分析图像或替用户填写通过；未收到实际评价时保持未验证。

人工确认完成前，`visual_baseline.status` 和 Work Item `globalStaticBaselineState` 只能保持 draft/pending，不能写入 `global-static-baseline-frozen`。确认后冻结身份必须同时绑定 baseline ID/version、`docs/visual-baseline.md`、冻结正文实际文件、primary anchor 和 selected candidate；候选、决定、brief、正文或锚点实际内容变化时按影响验证，摘要变化不使引用失效或重开三候选流程。该全局人工选择是独立硬门，不能替代每个场景 V2 的拆解图确认。

| 阶段 | 必须产物 | 允许状态 | 禁止旁路 |
| --- | --- | --- | --- |
| brief | 结构化 brief JSON、项目主题/受众/体验、三层刺激预算、generation batch；摘要仅可选追踪 | draft/in-progress | 空白方向、普通文本冒充结构化 brief、直接冻结 |
| 候选生成 | 恰好 3 张 `origin=generated` PNG/JPEG 效果图及各自 generation record、可选图片/记录 SHA（文件门检查真实魔数） | generated | 2/4 张、provided、重复 ID、扩展名伪装 |
| 人工选择 | 同屏呈现三张、五项逐候选人工结果、唯一 `SINGLE_HUMAN`/`CONFIRMED` 决定文件、selectedCandidateId、用户原文 | pending → confirmed | AUTO、pending、代写评价、选中失败或未验证候选 |
| 正式冻结 | `globalVisualBaselineSelectionRef`、冻结正文、真实风格指纹、primary anchor/selected candidate | global-static-baseline-frozen | 只写状态字段 |

## 全局视觉冻结表

游戏内信息表达按[游戏内文案](../../cocos-game-ui-layout/references/game-copy.md)进入 brief、候选效果图和冻结基线：优先图片、图标、数字与符号，只安排必要的短标签或说明，不把内部玩法描述直接绘制到界面。

全局规则在 G0/V0 的 brief 与三候选人工选择门中建立，并在确认后正式冻结；之后每个场景的 V1/V2 只冻结该场景的目标和方案，不得把场景 V2 当作全局基线选择。每项写明不变量、量化范围、允许变量、禁止项和证据：

| 系统 | 必须冻结的内容 |
| --- | --- |
| 世界幻想 | 玩家所处世界、时代/文化线索、情绪、叙事用途和项目主题辨识 |
| 玩家与体验 | 目标受众与依据、核心循环、体验目标、观看情境和持续注视区域 |
| 形状与轮廓 | 基础几何、圆锐比例、剪影复杂度、负形、边角和轮廓节奏 |
| 角色比例 | 头身比、五官位置、肢体粗细、手脚尺度、表情幅度和角色间比例 |
| 透视与镜头 | 投影方式、焦段感、俯仰角、地平线、镜头高度、景深和构图安全区 |
| 调色板与明度 | 主辅色、强调色、稀有度/状态色、明度层级、饱和度范围和对比预算 |
| 材质 | 表面类型、粗糙度、纹理尺度、体积、高光、阴影和磨损规则 |
| 光源 | 主光方向、色温、软硬度、环境光、轮廓光、投影方向和曝光范围 |
| 描边 | 是否使用、颜色、粗细、内外描边、缩放规则和不同系统的层级关系 |
| 渲染密度 | 单位面积细节、纹理频率、噪声、装饰密度、留白与视觉降噪规则 |
| 字体与排版 | 字族、字重、字号阶梯、行高、字距、数字样式、描边/阴影和文本安全区 |
| 图标语法 | 视角、轮廓、填充、圆角、线宽、体积、光源、状态与稀有度表达 |
| 面板与按钮 | 形状、层级、材质、边框、阴影、状态、按压反馈、主要/次要行动差异 |
| 动画 | 缓动、节奏、预备/命中/恢复、循环幅度、帧率、夸张度和角色动作语言 |
| VFX | 粒子形状、色彩、混合、亮度、持续时间、遮挡预算、峰值密度和降级方式 |
| 持续观看 | 常态/操作/峰值预算、重复触发与叠加上限、安静区域、收尾恢复、持续游玩复验情境 |

## 锚点与继承

1. 主锚点约束所有正式资源；分系统锚点只能细化对应系统，不能推翻主锚点。
2. 场景差异必须在全局不变量内实现。通过场景用途、构图焦点、专属对象、情绪、允许色彩范围和节奏形成差异，不得把所有页面做成同一模板，也不得让不同场景变成不同美术体系。
3. 局部资源只使用冻结表声明的允许变量。未声明变量默认不可变；需要新材质、光源、描边、比例、图标语法或渲染密度时先提交基线变更提案。
4. 原子资源必须绑定当前有效基线、锚点，以及适用的 V1/V2 `AUTO` 或 `USER_DECISION` 记录与视觉可交付结论。

## AI 生成包契约

每个 AI 生成包按固定顺序保存以下内容，不得只保留最终提示词：

1. **固定全局提示前缀**：从当前基线逐字引用世界幻想、形状、比例、镜头、调色板、材质、光源、描边、渲染密度和系统语法，并发送当前资产适用的受众、体验目标、视觉层级与刺激预算；同一基线版本内不得由单个资源改写。
2. **资产特定段**：只描述资源 ID、用途、构图、尺寸、透明要求、锚点、可见部件和允许变量。
3. **状态段**：描述默认、选中、错误、提示、购买、成功、失败、稀有度或动画时间点等适用状态。
4. **负向段**：逐字引用基线禁止项和负向词，并补充该资产特有的失败模式。
5. **生成记录**：保存系统实际选择的生成器及版本、种子、采样参数、参考输入及权属、遮罩/ControlNet 等控制输入、批次 ID、选择理由和后处理步骤。实际调用的工具身份必须保留，未暴露的版本、模型参数或种子明确记录 `not-provided`，不得编造。

生成结果仍须以锚点和跨资源证据供用户审阅。相同生成器、模型、种子、提示前缀或调色板只能证明生产条件相近，不能证明视觉一致。材质高光必须有主题与材质依据，不能把光晕、塑料高光或高饱和装饰当成默认质量增强；负向段按当前资源实际失败模式制定，不统一禁止某类项目风格。

上述 AI 专用字段只强制用于路线为 `ai-composite-raster` 且状态为 `producing`、`review` 或 `accepted` 的资源，不泛化到非 AI 生产路线。机器清单中的 AI `generation_record` 必须至少包含非空 `global_prompt_prefix`、`asset_prompt`、`state_prompt`、`negative_prompt`、实际生成器及版本、种子、非空 `reference_inputs` 路径列表和字符串 `postprocess` 数组；未暴露的版本写 `not-provided`。所有路线的 accepted 资源若没有 `source_file/source_files`，仍须满足公共生产身份：record ID、生成器及版本、时间、可执行命令/配方、输入来源和参数。状态段不适用时也必须显式说明原因；`--check-files` 必须验证每个 `reference_inputs` 文件。生成资产 `expected_assets.alpha=true` 时，策略与边缘类型由 `transparency_requirements` 冻结。纯色去背景只可用于 `hard-edge` 且主体与背景明显分离的素材；直接 Alpha 需有针对实际工具与边缘类型的验证，并解码 PNG 确认真实透明像素；复杂透明边缘走经验证的 Alpha、独立遮罩/人工创作、重新生成或有明确合同的 Cocos 特效。半透明、辉光、柔和阴影、毛发、玻璃与混合边缘不得阈值去背。生成记录需按实际路线绑定工具/版本、参数、后处理、原始输入与最终输出路径/SHA；只有背景去除路线保留背景颜色及实际尝试。已有真实透明图按 provided/reuse 资源合同接入，不伪造生成或去背记录；`alpha=false` 的完整场景背景按场景合同处理。

## 多资源一致性证据

V4 为每个生产包提交多资源联系表，并至少生成一张同屏组合截图。运行态默认使用 `visual_validation.mode=usability`，检查跨资源关系、可读性、边界、遮挡和交互；只有明确 `exact` 需求时才要求严格像素差异或完整视口/状态覆盖：

| 资源 ID | 基线 ID/版本/指纹 | 主锚点 | 分系统锚点 | 同屏对象 | 形状/比例 | 材质/光源/描边 | 色彩/密度 | 允许变量 | 偏差与结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

同屏截图必须覆盖会同时出现或由玩家连续看到的角色、图标、面板、按钮、场景对象与 VFX，并提供人工检查区域和要点。V4 再按[持续游玩验收](art-quality-contract.md#持续游玩验收)提交目标视口、重复操作、关键事件和叠加状态的动态片段，由用户确认运行态一致性与观看舒适；静态候选通过不代表持续游玩通过，孤立透明图、单图文件检查或作者声明不得单独通过。

## 漂移判定与处置

出现下列任一情况即判定视觉漂移或未验证：

- 资源未绑定当前基线 ID、版本、风格指纹或适用锚点；
- 实际基线文档或锚点不可读取，或内容不满足明确要求；
- 形状、角色比例、透视、材质、光源、描边、图标语法、字体、按钮、动画或 VFX 超出冻结规则和允许变量；
- 同屏对象像来自不同项目，或场景差异退化为同模板；
- 只有关键词、模型、调色板、单图或主观一致声明，没有联系表、同屏截图和区域事实；
- 新版本资源使旧锚点、状态、页面、图集、布局或运行证据失效。

按根因处置：字段、路径、绑定或生成包记录缺失先 `repair`；上游事实未变的正式文件、执行或机器证据偏差按 `revalidate` 重验当前门。只有方向/全局规则、冻结生产规格、构图、信息层级、资源槽或布局结构真实变化时才 `return` 到 V1/V2/V3/V4 中最早受影响阶段；普通候选身份变化只重验受影响证据，不触发回退。总控只核对绑定、版本和证据完整性；F2 机器出口只判断可确定性测量的合同事实，不代替用户对主题、质感、一致性与舒适度的视觉确认。

## 基线变更提案

禁止直接修改冻结基线。变更提案必须建立 Change Request，列出新旧基线、原因、影响、需要失效的高影响操作批准/证据、迁移计划、成本与重新执行 V2 拆解图确认的要求；V1/V2 使用 `AUTO` 或 `USER_DECISION` 记录，不写操作审批 pending。无副作用本地集成不因 A4 等级标签额外等待批准，外部写入、付费、真机、破坏性或外部删除、发布才进入精确操作批准。

新基线形成后，将旧决策和证据标为失效或限定范围，并从最早受影响阶段重验。明确规则下的忠实更新记录新 `AUTO` 决策；新方向或可见结构/交互取舍请求一次精确确认。

## 生成前全局基线硬门

全局三候选人工选择并正式冻结后，所有场景主图、reference target、宿主场景 contextual effect image 和原子生成式位图资产都必须引用同一份 `visual_baseline`。冻结基线必须是 `global-static-baseline-frozen`，并固定 `id`、`version`、`document=docs/visual-baseline.md` 与完整 `anchor_evidence`。项目具体美术风格只写入该正文和锚点证据，通用提示词不硬编码项目风格；候选阶段的生成记录使用 `global-visual-baseline-candidate-generation/1.0`，不冒充已经冻结的全局基线。

| 记录 | 必填生成身份 | 全局锚点 | 实际提示词 | 输出/证据 | 失效条件 |
| --- | --- | --- | --- | --- | --- |
| generated | baseline 四元组、`origin`、`style_drift_policy=forbid` | 全部 `style_reference_inputs` 实际路径，SHA 可省略 | `global_visual_consistency_prompt` + `full_prompt`，并证明实际发送 | `consistency_status=passed`、证据路径，SHA 可省略 | 基线/锚点/目标/提示词/证据身份变化 |
| provided | 仅 `origin=provided` | 不伪造生成输入 | 不要求生成记录 | 外部文件按普通文件门核验 | 实际文件内容或路径不再满足要求 |

生成式单图在绑定全局基线后按冻结路线交付：保留原始生成输入，执行透明处理，再由 Sharp 按合同归一化。比例不符时最多重生一次；第二次仍不符时，只有冻结焦点和安全事实允许才使用 `crop-and-resize-to-contract` 并绑定两次真实原始生成 attempt、尺寸、focus 和 `crop_rect`；若裁切会损伤主体、文字或透明轮廓，报告能力缺口并重新制定路线。适用于所有生成式位图的归一化规则仍为 `padding_policy=none`，禁止非等比拉伸、padding、contain、复制边缘及裁切冻结 `reference_target`。最终透明 PNG 的实际原始输入、归一化运行时文件、工具参数和后处理按实际路线登记，SHA 仅可选追踪；归一化保持比例、Alpha 和主体边界，不烘焙棋盘格。所有透明路线为同一实际候选生成深浅底预览，候选构建 SHA 与最终 PNG SHA 仅作可选追踪；V4 必须记录主体完整性、背景残留、色边和半透明区域检查，不能用格式检查替代。
