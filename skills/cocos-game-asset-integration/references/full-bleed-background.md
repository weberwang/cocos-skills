# 装饰性满幅背景

## 适用边界

只适用于不承载交互、文字、关键目标、碰撞、导航或玩法信息的屏幕空间装饰背景。
世界空间关卡、Tilemap、可交互物、玩法环境和影响遮挡判断的场景层，使用
`asset-production-routes.md` 的场景/Tilemap 或世界/玩法环境路线。

背景在 V1/V2 与关键对象联合确定性机器验证。默认 `visual_validation.mode=usability`，在不影响可读性、层级和玩法信息的前提下允许合理裁切与构图差异，但背景必须完全铺满当前可见场景，不允许留白、露边或仅覆盖安全区。完整覆盖是所有验收模式的硬约束。普通背景在已有明确需求或冻结基线且结构、布局、交互不变时记录 `AUTO`；新方向、焦点或高返工取舍只请求一次 `USER_DECISION`。Work Item 指定效果图忠实还原时受[视觉还原](visual-reconstruction.md)约束；只有 `exact` 或明确精确需求时，才把背景焦点、构图和可见裁切按严格容差判定，并要求对应决定记录。后续绑定当前决策记录。
响应式合同的详细字段和门禁以 [`cocos-game-ui-layout` 布局合同](../../cocos-game-ui-layout/references/layout-contract.md) 为准。

## 生产与适配

1. 适用 V1 时定义背景与玩家、目标、危险、交互、装饰的层级关系、焦点安全区、
   对比和遮挡预算，并冻结完整场景覆盖目标（实际可见 viewport）、裁切焦点、
   运行时覆盖和项目支持方向策略；安全区只约束关键 UI，不缩小背景边界。禁止留边与非等比拉伸；这些是适配器行为，不得替代生成式位图归一化合同。
2. 适用 V2 时同时放入关键对象和最高干扰状态，在代表性基准、窄/宽或支持方向视口
   验证背景覆盖、安全区、层级与最小可读性；单方向项目不要求另一方向，`exact` 或项目明确全覆盖需求才执行
   基准/最窄/最宽/支持方向/安全区完整矩阵。原子背景在 V4 动态轨迹中完成同类验证，只看空背景不能通过。
3. V3 记录可编辑源文件/生成记录、基准尺寸、最大纹理、内存、方向变体、
   裁切和延展规则，明确资源是否有覆盖目标 viewport 的像素/渐变/纹理容量。
4. 使用统一的 `cover-v1` 适配器。它不按横屏或竖屏预选缩放轴，而是每次根据资源与
   覆盖目标的实际比例计算 `scale=max(targetWidth/sourceWidth,
   targetHeight/sourceHeight)`，对两个轴使用同一个 scale。适配器以左上角为输出原点，
   根据冻结的归一化源图焦点和目标落点计算偏移，再将偏移限制在
   `[targetSize-displaySize, 0]`，确保焦点偏移不会暴露空隙。实现应复用
   [`full-bleed-background-adapter.mjs`](../scripts/full-bleed-background-adapter.mjs)，并在
   每次 resize、项目支持的方向变化或方向资源切换后重新计算；背景保持在最低装饰层且不接收输入。
   禁止用 `width>=height` 选择按宽或按高缩放。
5. V4 确定性机器 F2 **分别**验证资源本身的满幅能力（尺寸、透明边缘、延展/裁切）和
   适配规则；V4/F3 再在生产场景以代表性视口验证实际覆盖、safe area、UI 层级、
   动态 resize 和过渡。`exact` 或项目明确全覆盖需求才要求完整 viewport 矩阵和严格裁切/空隙容差。资源算法验证不是生产集成证据；Canvas ROI 只能补充。

测量字段、Hook 缺失时的“未验证”规则和禁止的假通过方式统一见 QA 的
[响应式视觉验证](../../cocos-game-qa-performance/references/responsive-visual-validation.md)。

项目合同至少冻结以下适配事实：`mode=cover-v1`、覆盖目标、源图归一化焦点、目标归一化
落点，以及可选的项目支持方向资源身份。方向资源只解决构图与像素容量问题；选择资源后仍须执行
同一个 `cover-v1` 算法。V4 Hook 必须报告实际资源尺寸、背景矩形和适配模式，使 QA 能同时
验证满幅、等比缩放、缩放值和焦点裁切，不能只报告 `backgroundCoversCanvas=true`。

不允许用纯色带、透明缝或复制拉伸掩盖未定义区域；如需生成式扩展，保留生成与编辑
记录。完整背景仅可替代装饰层，不得把交互场景扁平化。

背景生成式位图同样消费通用比例修正规则，并非背景专属能力：首次输出比例不符时最多
重生一次，第二次仍不符时，在已冻结焦点和安全事实允许的前提下记录两次真实原始生成
attempt 后执行 `crop-and-resize-to-contract`，否则先生成式延展到目标比例再执行普通归一化。只有需要透明交付的原子资产才按冻结的
透明策略处理；纯色去背仅适用于 hard-edge 且主体与背景明显分离的输入，完整 `alpha=false` 场景背景不走透明处理。背景去除 attempts
绑定真实原始输出；受控裁切可在含 Alpha 输入上执行，生成式延展应发生于透明处理之前。该规则同样适用于主体、UI、图标和其他生成式位图单图；禁止裁切冻结 `reference_target`，也禁止
非等比拉伸、padding、contain 和复制边缘。
