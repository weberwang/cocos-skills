# 本地服务查重与复用

启动 Cocos Creator 预览、测试服务器或其他长期运行的本地验证进程前，完整读取本文件。目标是复用同一项目已有的健康服务，避免重复进程占用 CPU、内存、端口和文件监听器。Creator 编辑器内置预览不需要额外进程时，不要为了遵循本流程另行启动服务。

## 启动前检查

1. 确定服务身份：解析后的项目根目录、服务类型、启动命令、配置模式、期望主机/端口和健康检查地址。仅端口相同或进程名相同不足以证明是同一服务。
2. 检查当前任务已记录的服务会话，并检查系统监听端口、进程命令行和工作目录。Windows 使用 PowerShell 7 的只读能力检查监听连接与进程；不要为查重安装常驻监控程序。
3. 对候选服务执行轻量健康检查，并核对返回页面、构建标识或项目特征。项目身份、模式和验证目标一致且服务健康时，直接复用其 URL、端口和进程，不再执行启动命令。
4. 端口被其他项目占用时，报告冲突；不得停止不属于当前任务的进程，也不得因为端口变化就重复启动同一项目。只有确认不存在可复用实例且验证确实需要时，才选择未占用端口启动一个新服务。

## 启动与记录

1. 启动前再次检查目标端口，避免检查与启动之间出现竞争。启动后记录项目根目录、服务类型、命令、模式、主机、端口、PID/会话、健康检查和启动者。
2. 同一任务的后续截图、浏览器检查、端到端测试和人工预览必须复用该记录。工具调用失败、页面暂未就绪或验证步骤切换时，不得直接再启动一个服务；先轮询或诊断原服务。
3. 原服务不健康时先确认进程归属、日志和端口状态。只有服务由当前任务启动且重启确有必要时才停止并替换；用户或其他任务启动的服务不得擅自终止。
4. 需要并行运行不同模式、版本或隔离状态时，先记录为何不能复用，并使用不同端口和明确身份；普通验证不得以“更方便”为由创建并行实例。

## 完成检查

1. 验证证据注明“复用已有服务”或“查重后新启动”，并记录最终 URL、端口与服务身份。
2. 完成前检查同一项目、同一模式是否存在重复监听实例。只处理当前任务明确启动的冗余实例，不停止无法确认归属的进程。
3. 服务是否保留按任务约定处理；无明确清理要求时，不擅自停止用户原有服务。报告当前任务新启动且仍在运行的服务，便于后续复用。
