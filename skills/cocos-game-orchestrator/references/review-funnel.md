# F0-F4 统一门

本文件只提供领域编排视图。唯一权威是全局控制面的 [控制模型](../../cocos-game-workflow-control/references/control-model.md)、[状态门](../../cocos-game-workflow-control/references/state-gates.md) 和结构化 Schema。

| 门 | 语义 | 编排交付 |
| --- | --- | --- |
| F0 | 范围与流程合规 | preflight 结果、当前任务范围、A 等级、路径/目标、基线与停止门；高影响操作另核对显式批准 |
| F1 | 规格一致性 | 实际 diff 到 approvedRequirements、模块、领域与阶段的追踪 |
| F2 | 领域质量 | 独立产品/架构/玩法/视觉/资源/音频/数值/QA 结论 |
| F3 | 工程验证 | 当前代码/diff 指纹、实际命令、环境、数据源、文件、判定与未覆盖项 |
| F4 | 高影响集成/发布决策 | 外部写入、付费、真机、破坏性或外部删除、发布的精确批准；无副作用本地 A4 不因等级标签额外审批；普通 A3 不适用 |

顺序、补签限制和三级处置由上述控制模型与状态门统一定义。本领域只负责按当前候选收集审查结论，不复制全局状态或风险枚举；未覆盖项记录在当前 Work Item 内，不扩大范围。

## 审查与返工收敛

审查只检查需求覆盖、明确缺陷、范围越界、硬门和当前证据真实性；不重复实施代理已经完成的同类探索，也不把“还可以有另一种实现”当作缺陷。进入执行/实施前满足入口、关键调用链或契约、任务范围、主要风险和验收目标明确且无直接冲突的最小条件后，A1/A2 冻结当前候选的范围、假设与验收边界，A3 冻结 `Implementation Package`；只有 A3 的实施代理按包执行，遇到需求/范围变化、实质冲突或无法实施才返回。

返工时记录触发原因、当前候选和真实影响范围，并调用控制面的 `repair`、`revalidate` 或 `return` 处置。没有真实失败或范围变化时不得继续优化式修改；A3 实施代理只按冻结的 Implementation Package 执行。用户决定、视觉/证据硬门和高影响操作批准仍由控制面校验。

## 领域返回结构

- Work Item、阶段、模块、领域、候选和基线身份。
- 覆盖事实、证据、阻断项、未覆盖项和领域结论。
- 实际 diff、路径所有者、A 等级与适用的高影响操作批准 ID。
- 证据失效条件、处置级别（`repair`/`revalidate`/`return`）和建议返回的最早状态。
- `affectedScope`、实际失效的下游阶段/单元以及是否需要显式 `RETURN`；不得用“退回阶段”文本代替处置分类。

领域审查者只能提议和审查。全局控制面独占状态迁移、Approval Ledger 和最终门结论。
