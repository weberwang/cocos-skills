# 依赖能力档与服务边界

本文件是 Cocos Creator 项目按需依赖能力档和 API/服务边界的唯一权威定义。先复用 Creator 编辑器、项目 TypeScript 能力、现有依赖和引擎原语，再按技术设计启用最小能力；初始化不得安装未被实际需求触发的依赖。

## 能力档

| 能力档 | 典型能力 | 启用边界 |
| --- | --- | --- |
| 核心档 | Cocos Creator、项目脚本语言及必要测试工具 | 仅项目基础运行、Creator 构建和测试所需 |
| 移动平台档 | Creator 原生构建、已采用的原生插件或最小 JSB 适配层 | 已批准的 iOS/Android 构建目标或具体设备能力；每个插件单独验证 |
| 数据/API 档 | 网络客户端、账号、远程配置、云存档和序列化 | 已有明确 API/数据契约，平台原语和现有依赖不足 |
| 复杂玩法档 | 寻路、额外物理、ECS、脚本或行为系统 | 核心玩法复杂度证明自研轻量方案不足 |
| 高级视觉档 | Shader、Spine、后处理、Tilemap 或资产生产工具 | 冻结视觉方向和预算确实需要，并有目标平台证据 |
| 商业能力档 | 支付、广告、分析、崩溃报告 | 用户明确批准商业/数据能力、合规范围和发布渠道 |

每个新增依赖在 TDD 记录能力档、启用原因、拒绝的 SDK/现有依赖/轻量方案、维护成本、运行时性能和平台风险、验证命令及所有者。一个项目可组合多个档位；能力未采用时不创建 `N/A` 条目。

## SDK 初始化归属

所有实际采用 SDK 的初始化调用、真实完成回调、幂等状态和初始化恢复统一放在 `assets/scripts/platform/initialize-sdks.ts`，由唯一应用装配入口一次投递；各 SDK 独立发起，不等待其他 SDK 或形成核心启动屏障。自身官方必需前置仍须核实，能力冲突只报告对应 SDK，不阻断其他分支或 Creator 首帧。原生插件封装 SDK API 细节，业务能力接口及广告位运行期恢复保持模块所有权，详见[SDK 统一初始化](../../cocos-game-architecture/references/sdk-initialization.md)。

## API 与服务边界

适用时记录：契约 ID/版本、服务端所有者、认证授权、幂等键与重试/超时策略、客户端兼容范围、数据或存档迁移、回滚、服务端/客户端测试边界、部署监控、备份恢复和外部故障降级。生产或发布变化按审核漏斗触发技术与 Release 通道。

如果任务不负责服务端实现，只记录外部依赖、所有者、契约与客户端边界，不扩张到服务端开发、部署或运维。密钥、令牌和个人数据不得进入仓库。
