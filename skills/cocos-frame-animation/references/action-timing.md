# 动画单元与共用时间轴

在动作时间轴分析时读取本文件。四类动画和两条来源路线共用这里的行为边界、时间规划与优化方法；类型制作细节由 [SKILL.md 的分类入口](../SKILL.md#分类入口)按用途路由。内部设计工件、正式提示词、真实视频/关键帧验收、帧序列预览和最终接入消费同一份动画计划。

## 动作分析与时间轴

制作前先按[玩法与意图设计方法](intent-driven-design.md)建立“玩法目的 → 表现意图 → 时间约束 → 姿态与阶段节奏 → 检查点”的推导并保存到内部设计工件，不直接套用阶段比例。明确需求时直接采用合理表现参数并写提示词、制作真实候选；不把分析文字或时间轴表作为独立人工确认门：

- 明确用途、触发、初态、终态、完整行为边界与现有输入机制，区分已知要求、建议和待确定项。
- 解释阶段顺序与关键变化的理由：普通动画依据对象结构与运动规律，角色动作依据重心、承重、发力、惯性和道具轨迹，特效依据出现、峰值与消散，UI 依据响应、信息状态与结束方式；只分析当前类型实际需要的阶段。
- 说明前后阶段及外部动作如何承接、是否循环、周期如何闭合、进入/退出或终态保持如何结束；缺失的玩法条件保留待确定，不补设行为权限。
- 结合游戏类型、操作与反馈速度、已有玩法时序、对象性质和动作目的，逐个分析速度变化、主次、停顿与事件关系，再推导各自动画的游戏时长、阶段区间、关键姿态/视觉状态、事件时点与 FPS，并记录节奏取舍、运动范围和显示尺寸的推理依据。视频路线同时收齐全部动作，按[合批消耗比较](region-planning.md#视频条数与消耗比较)选择 768p/2K 区域排布、条数和预计消耗；已有预算及外部操作授权边界继续生效。

首次交付直接展示真实视频候选/预览或真实图片帧，并附简短检查点；推导理由、阶段表和取舍保存在内部工件。仅当玩法事件、时长或行为权限确实缺失且无法从已有规则推导时，询问受影响动作并暂停该动作，其它明确动作继续推进。用户确认实际素材时可同时接受该素材表现出的时序，不另行确认文字复述。视频仍须人工验收实际抽帧输入后才能抽帧；图片首尾、关键帧及递归父图仍逐张人工确认，设计记录不代替真实素材验收。

## 动作分组

- 按行为语义确定动画单元：记录触发条件、初态、完整阶段序列、终态或循环周期，以及播放期间需要表达的事件。同一次触发下连续完成的阶段属于同一单元，共享时间轴与完整预览；阶段数量和事件数量不决定视频任务数量。
- 具有独立触发、分支、取消、复用或生命周期的行为可以划为不同单元，记录边界与理由。边界依据现有玩法或状态合同，不由用途类型、阶段数或输入次数反推。区分行为单元、运行时动画 key 和源素材包装：多个 key 可以来自同一完整素材，一个素材文件也不能代替行为边界定义。
- 连续单元内部默认整体制作。确需分段生产时，先写明生产理由、各段入姿/出姿、锚点、连接条件与总时间轴，制作后用真实组合序列检查连续性。不得因任务清单分行、事件数量、工具参数或生成器时长限制自行切断行为。
- 既有完整连击即使由多个输入门逐段推进，仍在共享时间轴记录完整段序、事件和输入衔接；不因拳数拆成独立生成任务。美术计划沿用现有输入、推进、取消与伤害规则，缺失的玩法决策先标明待确定，不自行增加攻击、自动连击或伤害。
- 独立动画单元可按[区域规划](region-planning.md)合批。视频在多个固定区域同时呈现；图片合批须遵守[多区域图片](image-inbetween.md#多区域图片)的局部时间与引用约束。每个区域分别记录类型、完整时间轴、有效源区间或帧位、游戏时间映射、FPS 和输出尺寸。类型、播放方式、行为单元、来源批次和 key 数量分别决定。

当前抽帧工具每次为一个固定区域输出一个覆盖全部输入帧的动画 key；未指定区域时使用整幅画布。一个批次的不同区域分别传入 `--region x,y,width,height`，生成各自图集和合同并共享视频来源。玩法确需按时间边界生成多个 key 时，先剪出保留整幅空间布局的派生输入，再按对应区域抽帧；保留整组来源与连续预览，不直接缩小报告帧范围来冒充时间裁剪。

## 游戏时间先于来源

先读取已有玩法时序；已定义的总时长或循环周期作为设计约束，在该约束内安排关键事件与阶段。总时长未定义时，依据游戏特点、玩法响应和行为目的，先确定必要事件、关键姿态和各阶段节奏，再汇总各自动画的合理总时长或循环周期并记录推理依据；不先套用生成器或示例的固定时长再硬凑阶段。仅当时长确实不能推导且会改变玩法行为时询问用户。相邻阶段按行为要求直接过渡，只有计划明确要求时才返回初态、重复准备或保持姿态；各阶段不必等长。

同一视频内的独立动画共享来源画布，不要求共享游戏时长或节奏。各组可采用不同总时长、阶段比例、速度变化、停顿、循环周期和 FPS；只有实际玩法需要同步时才约束对应事件，不据此强制全部动作同时开始、同时结束或等长。合批方案承接各自动画时间轴，不能为了统一视频时长而拉长短动作、压缩长动作、补静止等待或添加计划外循环。

动画计划保存为项目内设计工件；分类与优化参数不扩展报告或 accepted 合同 schema。至少包含：

| 信息 | 要求 |
| --- | --- |
| 用途类型与视觉依据 | 普通/角色/特效/UI 帧动画、选用的分类参考、真实美术基线的来源与身份、对象性质；设计参数与真实素材验收分开，见[职责边界](workflow-integration.md#设计与美术的边界) |
| 玩法目的与表现意图 | 触发者/观看者、玩家需要理解或应对的内容、希望表达的性质、既有玩法时间约束；记录适用方法、推导理由和可观察检查点，见[玩法与意图设计方法](intent-driven-design.md) |
| 来源路线 | 视频抽帧或图片递归补帧、选择依据；是否合批及区域的独立映射 |
| 行为单元与边界 | 名称、触发条件、初态、阶段顺序、终态或循环周期；现有输入/状态机制与生产、运行时分段原因 |
| 每个动画的时长与 FPS | 各动画单元的游戏总时长或循环周期（毫秒）、目标 FPS 与预计帧数，以及游戏特点和玩法时序下的取舍依据；不以视频批次统一时长 |
| 阶段区间与关键姿态 | 每段开始/结束毫秒、运动/过渡/保持意图、关键姿态或关键视觉状态与连接方式；区间覆盖整组，无未说明空档 |
| 事件与衔接 | 事件名称、作用、同一时间轴上的毫秒与目标帧、既有输入/状态衔接窗口；无事件时明确记录无 |
| 前后动作与切换 | 涉及动作/状态交接时记录前置与后续单元、入态/出态、过渡区间和允许切换条件；角色具体判断见[衔接与循环设计](character-animation.md#衔接与循环设计)；无外部衔接时明确记录无，未定义项保留待确定 |
| 播放与保持 | 明确是否循环；循环、单次、组合、终态保持分别记录，可按任务组合；有意定格的区间、用途、时长或结束条件；循环周期、闭合要求及进入/退出条件，不能把组合等同循环 |
| 锚点与允许位移 | 固定语义根、视角、朝向、允许位移的方向/轨迹/范围及与运行时位置的关系，不把工具默认根点当作设计结论 |
| 运动范围与显示尺寸 | 依据真实美术与完整动作推理运动包络、安全边距、目标显示宽高、输出 cell；区分推断值与实测值，由真实素材检查完整入框；获明确授权的裁剪例外单独记录 |
| 背景与叠加 | 是否保留背景、硬边/真实 Alpha/遮罩或修帧方案；涉及叠加时记录透明度、颜色和混合要求 |
| 类型表现参数 | 重量感、夸张程度、速度变化、停顿和跟随运动的取舍及依据；不适用的项明确不采用 |
| 来源批次与区域 | 批次 ID、画幅、预期/实际宽高、区域 ID 和 x/y/width/height、效果图尺寸推理依据、独立输出尺寸；视频在 768p/2K 中比较能覆盖全部动作的条数、总生成时长和整组消耗，记录候选排布与推荐理由；图片沿用自身分辨率约定；视频音轨或独立声音方案 |
| 来源时间映射 | 视频时长独立记录，补齐有效区间与重定时；图片记录目标帧位、关键帧、父图依赖和生成顺序，播放顺序按游戏时间排序 |

预计帧数按游戏时长乘 FPS 计算并记录取整规则，事件映射至可播放帧；量化容差最多一个目标帧间隔，不能丢失关键事件或短促衔接。若当前 FPS 无法表达事件，内部调整 FPS 或动作设计并直接反映到真实候选，不盲目拉长动作；只有调整涉及无法推导的玩法时长或行为权限才询问。

图片工具使用 `N = round(游戏毫秒 × FPS / 1000)`，此路线至少两帧。播放帧位为 `0..N-1`，时点为 `index × 1000 / FPS`，最后一帧保持一个帧间隔，播放总时长为 `N / FPS`。首尾之外的必要关键姿态和事件先映射到实际帧位；多个不同状态落到同一帧时先解决时间设计冲突，不能靠增加递归层数补救。循环另有 `index=N` 的闭合参考，供最后区间补帧但不进入图集。递归只填有限目标槽位，不强制 `3、5、9、17…`。

提示词对每个阶段同时写出时间区间、动作意图、关键事件和到下一阶段的过渡；真实视频及帧序列按同一游戏时间轴审阅。只列姿态名称或笼统写“自然流畅”，不能代替阶段之间的时间与连接约束。

游戏时长、阶段比例、命中停顿、连击次数、FPS 和音频方案由当前用途、玩法与视觉基线确定。示例或工具缺省值不能作为全局制作标准，也不能把当前拳手或三连击案例推广到其他动画。视频分辨率与最少可行条数按[合批消耗比较](region-planning.md#视频条数与消耗比较)推理并记录；图片保留[独立分辨率约定](region-planning.md#图片分辨率约定)。生成时长为工具能力与区域覆盖服务，不反向改变游戏时长。

## 共用质量与优化

先把反馈对应到可观察的问题，再使用当前类型规则调整；共用质量标准如下：

| 标准 | 判断依据与优化方向 |
| --- | --- |
| 可读性 | 在目标显示尺寸下，初态、主要变化、关键姿态/视觉峰值和终态是否可辨；优先调整轮廓、幅度和关键状态，而非单纯加帧 |
| 节奏 | 阶段长度、速度变化和保持是否表达对象性质与任务意图；按阶段调整时间映射，不统一加速或套用蓄力、爆发、固定停顿 |
| 主次关系 | 主对象、关键信息与事件是否先被识别；辅助运动、光效和装饰的强度与出现时点是否符合层次 |
| 连续性 | 相邻阶段、循环接缝或组合连接是否出现未计划的位置、形态、方向或速度跳变；保留有意保持、遮挡和类型允许的跳变 |
| 事件同步 | 可见动作/效果与已有玩法、宿主或 UI 状态事件是否对齐；修正事件表达和帧时序，不用美术方案改触发次数与行为权限 |

重量感、夸张、停顿与跟随运动是可配置的表现手段，按类型和视觉基线说明采用理由与范围。普通机械运动可以强调规律，角色发力可以使用速度反差，特效可以强调峰值与衰减，UI 可以强调响应和信息层次；这些判断只在对应任务中应用。

优化时先区分时间问题与图像问题：视频的阶段过长、事件错位或重复周期先整理有效区间与阶段重定时，最终输入人工验收后抽帧；图片按内部工件的目标槽位重排阶段关键帧和补帧计划。轮廓、姿态、轨迹、颜色与边缘问题修对应帧及相邻帧。同一目标下的局部纠错与细化直接返修并展示前后对照，更新内部时间轴记录，不再单独要求确认文字方案；只有玩法语义或来源路线实质变化才询问。实际视频或关键帧改变后仍须人工重验受影响素材。两类修正均保留已修图成果并更新来源映射、产物与证据，不以来源缺陷作为最终验收要求。

## 运动、保持与循环

运动阶段须在计划区间内持续推进；静止保持必须在计划中标注区间与意图，不能因源素材没有后续动作就自动延长。低幅度运动仍属于运动，不能默认定格；单次动画按计划结束或保持终态，不自动循环或添加等待。

循环动画在设计中明确周期、闭合及进入/退出要求，在真实视频和最终帧序列预览中跨周期连续播放，覆盖完整周期内部与相邻周期接缝。除计划明确允许的跳变外，接缝应保持姿态、位置、运动方向与速度连续，不重复保持端点，不由播放器加入计划外等待。仅确认首末帧位置相同不能证明循环通过。

缓动极值处短暂减速、有意停顿和终态保持按动作计划保留；未计划的定格、空白等待与重复端点应修正。不要自动删除所有相似帧，避免破坏低幅度运动或设计中的保持阶段。人工审阅分别判断阶段内运动、阶段连接、事件时刻与播放边界，不以某一类动作的运动模式要求所有动画。

## 视频节奏整理

当前 `video-to-atlas.mjs` 支持 `--region` 空间裁剪，但仍对输入视频的完整时间段抽帧，并使用同一 FPS 播放全部帧；没有时间区间选择、分段剪辑或独立播放速度参数。降低 `--fps` 同时减少采样帧数并按同一帧率播放，不能缩短动作。不能把区域裁剪当作时间裁剪，也不要只改报告中的帧率。

1. 保留用户原视频，按区域核对已确认动画计划，分别记录阶段、事件、停顿的实际源时间。某个区域的源时长满足其游戏时序时，可直接作为待人工验收的抽帧输入，不额外变速；验收通过后才抽帧。
2. 某区域含前后等待、重复周期或未计划停顿时，用本地剪辑或 `ffmpeg` 先选择该动画的有效区间；多区间依原顺序连接。较长但内容完整时按阶段重定时，不用整体加速掩盖阶段错误。不同区域的有效时间段不必相同，分别准备对应输入。
3. 将整理结果保存为独立派生视频，保留整幅空间布局、尺寸与朝向，再由抽帧工具裁区域，避免重复裁剪或原点失配。源中存在的音轨按当前任务合同维护与时间映射对应的处理，记录是否保留及处理配置。保留原视频与派生视频的路径和 SHA、剪辑命令/配置及各段源时间到游戏时间的映射。生成器最短交付时长只影响源视频与映射，不改变各自动画时长，不用静止填充凑时长。
4. 将实际最终输入视频连同简短检查点直接交付人工验收；原视频已适配时直接验收原视频，发生整理时验收派生视频。用户对实际视频的确认同时接受其可见表现时序，不另行提交文字复述确认。缺失动作、不能平滑连接或其它验收失败先修正视频并重提，未通过前不抽帧，也不以计划在抽帧后补齐为由放行。验收核对实际路径、区域与时间映射，不检查 SHA；该身份变化时重新验收。通过后将该视频作为 `--input-video` 与合同中的 `source_video`，报告 SHA 对应实际抽帧输入；原视频、验收依据和时间映射保存在 Work Item 设计证据中，不伪造已有源视频事件。
5. 抽帧后逐个核对 `帧数 / FPS` 与各自动画的游戏时长（最多一个目标帧间隔的量化差）、各事件帧、阶段顺序和计划保持，不与批次视频总时长或其他区域帧数比较来强求一致。偏差先修正时间映射或按来源顺序删去未计划保持帧，再交付人工检查完整行为、阶段连接与对应的单次/循环/终态播放方式；文件 SHA、格式校验和报告 `PASS` 不能证明节奏通过。

抽帧后才发现时间问题时，可以按来源顺序删去未计划保持帧，或在已有帧槽位修正过渡姿态；保留已修正图片，重新连续编号，并保留剩余帧真实的来源时间戳与 SHA，更新来源映射、图集、报告与预览。现有合同要求来源时间戳严格递增，不支持交换来源顺序、复制来源帧或无来源的新帧；需要这些操作时，先将编辑结果保存为新的真实视频来源，人工验收该输入后再抽帧、记录其 SHA 与来源时间，并迁移修图成果，不以改写来源字段绕过校验。为落实内部时间轴而整理源视频不需额外设计确认，但新的实际抽帧输入须人工重验；同一目标下调整游戏时长、阶段节奏、关键事件或有意停顿时更新内部记录并直接返修候选，只有改变玩法语义或行为权限才询问。
