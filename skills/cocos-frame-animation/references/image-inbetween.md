# 固定画布图片递归补帧

仅在用户明确选择图片来源或确认切换时读取本文件，同时读取当前用途的一份分类参考和[共用时间轴](action-timing.md)。未指定来源时按[来源路线](../SKILL.md#来源路线)默认使用视频抽帧。分类决定运动与验收依据，来源路线决定怎样取得帧；本文件不重复共用流程。

## 适用与边界

以真实图片生成/编辑制作首尾和必要关键帧，用相邻两张已确认图片作为参考生成指定时点的中间帧，递归填满目标槽位。适合需要控制关键姿态、造型一致性或透明边缘的任务。大角度转身、遮挡、接触、肢体交叉、复杂组合或首尾相同的循环，先锁定阶段关键姿态再补区间，避免生成器凭两个端点自行发明轨迹。

双图参考生成不保证像素对应、骨架、锚点或运动规律正确。先看父图，再看生成帧在当前类型下的轮廓、重心/运动规律、主次和事件；每层通过后才继续其子区间。工具未提供的光流、时间插值系数、种子、精确宽高或模型参数不得虚构。

时间轴推导记录与外部操作授权沿用[接入合同](workflow-integration.md#动作设计与素材确认)。先完成设计理念说明并取得用户对当前动作方案的明确确认，再在已有授权范围内制作真实首尾和关键帧；首尾、每张关键帧及递归父图仍须经人工确认，才放行依赖它的制作。实际图片生成/编辑交给 `image_generator` 子代理，动画执行代理提供完整任务包并集成结果；本地规划和打包脚本不会调用生成服务。实际生成、付费或外部写入必须处于已有授权范围，路线选择不构成授权。

## 固定画布

先确定完整表演、动作轨迹和观看重点，再据此推导 `宽×高`、完整运动包络、安全边距、背景处理与目标 cell；同时记录资源坐标系、语义锚点的打包含义，以及任务确实要求时的固定机位。固定画布、区域坐标和资源锚点不锁定角色朝向、姿态、透视投影大小或画面内根位置。允许按表演需要侧身、背身、旋转、翻腾、透视变化、遮挡、夸张形变和位移；一致性以角色身份与动作过程连贯为核心，按设计解释各阶段变化。除非任务明确要求稳定视角或造型，不把基线中的单一朝向/比例当作全程硬约束。对象资源布局依据真实美术基线及完整运动范围，不能继承设计示意的占位造型或包围盒；遵守[设计与美术的边界](workflow-integration.md#设计与美术的边界)。图片默认 **768p**，具体画幅换成明确宽高；当前已授权预算与工具能力内确需 **2K** 时，按[图片分辨率约定](region-planning.md#图片分辨率约定)记录依据并直接制作，只有新增费用、超预算或改变授权范围时才请求批准。视频的少条数与消耗比较不替代图片的固定画布和逐张确认规则。

所有最终帧共享同一真实画布。图片工具的可用参数以当前接口为准：有本地文件时使用 `referenced_image_paths` 引用父图与必要基线，至少能包含两张父图；只在目标图没有本地路径时使用会话图引用，不同时使用两种引用方式。透明素材设置真实透明背景，保留原有 Alpha。若工具只支持提示词描述尺寸或固定生成档位，先核实实际返回宽高，再统一规范化到已冻结画布，保存原图和变换记录。不得把提示词要求写成实际尺寸事实。

尺寸规范化保持完整运动范围，以任务适用的统一画布变换/留白和资源锚点映射处理，必要时局部修图；同一动画不得逐帧改变缩放或锚点来抵消表演中的主体位移、转向和透视变化。不能逐帧按主体包围盒裁切、独立居中或拉伸身体来凑一致；需要改变资源锚点、运动包络或画布时更新内部时间轴记录，并直接制作受影响的真实候选供用户审阅。若改变已确认的目标感受、核心动作方案、玩法语义或来源路线，先重新说明并确认；局部空间修正沿当前方案返修。若原图内容被裁断，扩图/补绘或在已有授权内重做该图，不能靠留白恢复已丢失内容。

## 首尾、关键帧与递归

1. 按内部推导的游戏时长和 FPS 建立有限目标槽位，将阶段关键姿态及事件映射到索引。先解决同一帧位的姿态冲突；不把增加递归深度当作提高时间分辨率。
2. 从真实美术基线制作首帧；用户已指定首帧图片时优先沿用该图，按资源合同处理画布与锚点，不能为了贴合设计示意而重新设计造型。角色首帧须考虑前置动作的出姿，检查视觉基线、固定画布与锚点并确认首帧后，以首帧和有效基线作参考制作尾端点：非循环按已定终态及后续动作入姿设计，循环按闭合状态设计参考图，不能把两种尾端点混用。尾端点通过后继续。
3. 在首尾之间按游戏时点顺序逐张制作必要阶段关键帧。首个关键帧以已确认首帧为动作起点，具备可用视觉内容时以其为主要编辑依据，后续以最近的前序已确认关键帧承接状态；需要时再参考已确认的后侧端点或基线，并分别标明各图用途。首帧为空透明时，使用真实美术基线和内部记录的阶段设计，不能把空图当作充分造型参考。同一连续行为中，不能让各阶段只共同参考首尾而独立发明姿态，不能批量制作尚未确认帧的后继。每张完成[一致性及衔接门](#关键帧的一致性与衔接门)，人工确认后才制作下一关键帧。主动行为检查准备、发力、事件姿态与回收；循环检查周期内部极值/承重点；普通、特效、UI 只选各自真正需要的状态，不强加角色蓄力或战斗爆发。
4. 对相邻已确认关键帧区间，选一个尚未填充的目标帧位，使用两张实际父图、统一基线和该帧时点/阶段参数生成中间帧。父图不一定按生成先后排列，提示词明确“左图较早、右图较晚”。本地规划默认按索引中点填充；具体轨迹、非匀速变化和停顿仍由内部时间轴工件决定，不是姿态平均。
5. 本帧同样完成一致性及衔接门，人工确认后再递归左右子区间。错误先修本帧，不拿错误父图继续生成；已正确的其它帧和修图成果保留。不同对象或无依赖区间可独立推进，不能借并行绕过当前依赖的人工确认。
6. 全部目标帧位齐备后按 `index/game_time_ms` 排序打包，跨周期或完整单次人工播放检查。生成顺序和文件名顺序不决定播放顺序。

帧数遵循[共用时间轴](action-timing.md#游戏时间先于来源)，不强制 `2^k+1`。非循环的尾帧是最后一个实际播放槽位；终态保持到动画外部的时长由现有状态合同控制，不虚构逐帧时长参数。

循环额外制作 `index=N` 的闭合参考，位于量化周期结束时，供最后区间补帧；打包只使用 `0..N-1`。闭合图可以与首图表现相同，但周期内部仍须有承重、极值、方向与速度等必要关键状态。闭合参考不进入图集，避免重复端点；合法停顿和低幅度运动保留，不能自动删相似帧。进入/退出循环的过渡按既有行为边界规划，不把每次进入或退出都塞进循环体；正式预览还需检查最后播放帧到首帧的接缝，以及允许的外部动作交接。

使用本地规划器（示例参数只说明接口，按当前任务选时长、FPS 和关键帧位）：

```powershell
node <skill-dir>/scripts/image-inbetween-plan.mjs `
  --duration-ms 1000 --fps 6 --keyframes 2 --no-loop `
  --output-plan evidence/animation.inbetween-plan.json
```

计划的 `steps` 按生成依赖排列，含 `index`、`game_time_ms`、`kind`、`parents` 和 `reference_only`；这是采样与递归计划，不代表图片已经生成、人工通过或允许批量执行。阶段关键帧的实际参考顺序按上述逐张确认规则另记设计工件，来源清单记录实际使用的父图，不照抄规划器的父索引冒充工具输入。循环使用 `--loop`，未填写关键帧不表示复杂循环可以只凭两个端点完成。当前规划/来源工具接受 2 到 100,000 个播放槽位，这是本地工具的规模保护；实际图集还受最大边长约束，不是制作时长或 FPS 默认要求。

## 关键帧的一致性与衔接门

固定画布与资源映射约束输出容器，不代表主体必须固定在同一屏幕位置、朝向或投影比例。设计工件应区分角色身份特征、任务要求稳定的机位/造型、当前阶段预期变化和动作状态；机位与主体朝向分别记录。依据真实基线及相邻已确认帧检查身份延续、动作因果、轨迹和阶段变化，不要求每帧轮廓、可见比例、透视或屏幕左右位置相同，也不从占位示意取形体或关节点。

| 检查层 | 判断与放行依据 |
| --- | --- |
| 文件与映射 | 核对实际原图、父图、提示词、画布尺寸和整幅规范化；SHA 只作可选追踪，不是放行条件。锚点数值相同仅说明记录相同，不说明实际主体落在同一位置；全图 Alpha 边界只判断完整入框，不能代替身体尺度或接触位置检查 |
| 类型相关的一致性 | 角色比较可识别身份特征、装备归属、动作因果与接触关系；按设计判断头身比例、轮廓、朝向、透视和遮挡变化是否合理，不因可见比例变化而判错。普通动画比较安装点、转轴与部件尺寸；特效比较宿主定位、约定风格及阶段形态；UI 比较布局边界、图标与文字。特效扩散、对象形变或主体位移按内部设计工件判断，不统一锁死外包围盒 |
| 阶段状态与衔接 | 检查当前帧是否实现准备、发力、转向、腾空、峰值、回收、消散或状态切换等本任务目的；与前后已确认状态比较运动方向、接触、遮挡和轨迹是否符合设计且可承接。预期的旋转、翻腾、透视缩短和大幅位移属于表演变化；保持造型却没有实现当前阶段，同样不能放行 |

制作提示词先描述本帧动作过程、朝向演变、空间轨迹和节奏，再说明“哪张是编辑目标、哪张负责前序动作、哪张负责终态或身份”，补充需延续的身份特征和本任务的资源约束。只在任务需要时要求固定机位、造型或朝向；不要无差别加入“禁止旋转”“始终正面”等负面约束。复杂动作补帧困难时，优先补必要关键姿态、明确轨迹或修正源图，再判断当前来源能否继续；不得自动简化成正面微动，也不得擅自切换已选来源。可信参考只保留解决本帧问题所需的已确认图，不混入未确认图、被否定帧或未区分各图用途的造型图。局部返修可将当前未确认或被否定候选仅作为明确标识的编辑目标，指出待纠错部分及需保留的正确部分；身份、轨迹和任务要求仍取自已确认真实基线及相邻帧，不能把候选中的缺陷当作必须延续的条件。返修输入与输出的真实身份记入修正记录，不把同索引的返修输入登记为自身父图，修正后重新人工确认才可作为后继的可信父图。角色提示词说明同一肢体/持物手的连续身份、承重脚和具体道具轨迹；后拉不等于换手，压髋不自动等于整体缩小，发力变化按设计决定是否需要主体透视或比例变化。

交付同一画布原点、同一显示倍率的真实基线与当前帧对照，支持手动切换，并列出当前类型的检查点。至少比较前序已确认帧，存在后侧已确认邻帧时也检查其衔接；目标显示尺寸下由用户人工确认。不能按各帧主体包围盒对齐、缩放或居中后展示，以免隐藏漂移。只含关键帧的预览标明缺失帧位和临时保持；它用于姿态与轨迹审阅，不能因为关键帧间跳切就宣称完整动作连贯，也不能把真实比例变化解释为缺少过渡帧。

文件检查结果、当前阶段实现情况和人工视觉状态分别记录在设计工件。文件通过而人工未确认时，不能作为后继关键帧或递归补帧的父图；泛泛的“继续”或先前首尾确认不替代当前帧确认。无需增加报告或 accepted schema 字段，也不默认新增人体自动检测脚本或截图验收。

出现漂移、身份变化或阶段错误时，暂停受影响的依赖链，先核查原图和整幅映射，再以最近可用的已确认真实帧修正当前候选。保留其它已确认成果与历史来源；已制作后代逐项复查，不能仅改父图 SHA。禁止用补帧掩盖缺陷、逐帧整体拉缩/居中凑一致，或复制静止帧假装完成动作。局部修正沿用已有授权，提交新候选重新确认；任务包限定返修范围与重试停止条件，工具无法稳定满足时停止后继制作，报告限制并提出可审查的替代路线，不自动扩大批量、升级分辨率或更换来源方案。

## 提示词与逐层检查

提示词沿用“共用视觉与资源约束＋当前类型规则＋当前帧参数”，每次生成保存实际发送内容和真实参考图身份。时间轴设计只提供文字动作与时间参数，其图表或占位示意不进入 `referenced_image_paths` 或会话图引用；视觉参考使用真实基线及实际父图。至少写清：

| 内容 | 具体判断 |
| --- | --- |
| 共用约束 | 基线身份/材质/配色，固定画布、资源锚点映射、完整运动包络和透明背景；机位、造型、朝向、投影比例与根位置仅在任务明确要求时固定，并将机位与主体朝向分别描述；不烘入标签、索引或辅助线 |
| 父图与目标帧 | 左右父图索引、实际文件和可选 SHA、对应游戏时点、本帧索引/时点和所属阶段；要表达的关键状态及与两侧衔接 |
| 类型规则 | 普通检查运动轴/安装点/状态；角色检查身份可识别性、重心、发力链/接触，并核对轮廓变化是否符合计划动作；特效检查峰值、透明与消散；UI 检查响应状态、文字/信息和布局边界 |
| 时间意图 | 内部工件记录的轨迹和速度变化、本帧距事件的先后关系、有意保持或跟随运动；不以“中间姿态”代替具体位置与动作 |

例如某角色区间左图是准备末态、右图是命中态，中点时间可能仍在蓄势或已接近爆发，须按计划写出重心、躯干转动、肢体轨迹与事件先后。普通机械匀速转动则按角度和轴心判断；特效按可见面积/亮度/衰减判断。不要统一套用角色停顿。

重点发现无意的身份漂移、肢体数量错误、违背设计的遮挡/接触、与轨迹不符的位置突跳、无计划的方向反转、闪色、局部粘连、半透明边缘断裂，以及未计划的保持或峰值偏移。合理的转向、透视变化、轮廓变化、遮挡和主体移动不作为缺陷；资源锚点记录稳定也不要求主体在画面中的根位置稳定。人工检查目标显示尺寸；特效叠加深浅背景，UI 放入实际布局。文件门不证明动作、节奏或视觉正确，也不自动截图。

## 多区域图片

允许同一组源图的多个固定区域分别制作动画；每个区域单独记录用途类型、资源锚点、目标尺寸、FPS、关键帧位、有效帧选择和游戏时间映射。固定采样区域与区域坐标只定义容器，不锁定其中角色的朝向、姿态或画面内运动。相同来源可以共享生成记录和原图，输出图集与来源清单按区域独立绑定。

仅在各区域当前帧状态可同时明确描述时合批双图生成。补某个区域时，以实际两张父画布或该区域的真实派生参考为输入，约束其它区域保持已有内容；生成器改动其它区域时，只合成经检查的目标区域回固定画布并记录修正来源。各区域时间轴不同，可从批次源图选择不同帧并建立各自来源清单，`game_time_ms` 表示该区域的游戏帧位，生成时的批次时间另存设计工件。不得按全画布统一中点强迫所有区域同一阶段，也不覆盖已有修图。

当前工具每次打包一个固定区域。对完整源画布使用 `--region x,y,width,height`，锚点是区域内坐标；使用已经裁出的真实派生图片时改为对应小画布，不再套原区域偏移。复杂或互相干扰的区域可拆来源批次，记录原因，保持完整行为时间轴。

## 真实来源与修图记录

图片使用 `cocos-image-frame-source/1` 来源清单，所有 `file` 相对 `--project-root`，包括图、父图、生成记录、参考基线和修图记录；拒绝项目外或符号链接逃逸。来源包含 `canvas`、`duration_ms`、`fps`、`loop` 和完整 `frames`。各帧索引必须连续覆盖计划，条目填写顺序可以不同，游戏时间必须对应槽位；SHA 字段可选，仅用于追踪实际文件身份，不作为验收门。

每帧字段：

| 字段 | 含义 |
| --- | --- |
| `index/game_time_ms/kind` | 游戏帧位、毫秒与 endpoint/keyframe/inbetween 类型；不是视频来源时间戳 |
| `source_image` | 实际生成原图的 file；SHA 可选，保留其实际输出尺寸 |
| `image` | 最终固定画布图片的 file；SHA 可选，打包使用此图 |
| `generation_record` | 实际生成记录 JSON 的 file，SHA 可省略，包含非空 prompt、reference_images 与 output_image；输出绑定 source_image，真实参考包含父图 |
| `parents` | 实际用于生成的父图快照 `{index,file,sha256?}`；SHA 可选，中间帧必须两个父索引且位于两侧，依赖无环 |
| `repairs`（有修正时） | `{before,after,record}` 的顺序链，各项绑定实际 file，SHA 可选；从 source_image 连到 image，record 记录问题、方法和前后身份 |

尾端点引用首帧；阶段关键帧可引用至多两张已制作图。生成记录可附实际返回的工具信息；未返回的模型、版本、种子或记录 ID 标记未提供，不捏造。若提供图像 SHA，它只能辅助核对文件身份，不能证明生成器遵循提示词，也不能替代人工确认。

修正文件使用新路径/版本，不覆盖原图、父图快照或已有修图。父图快照必须来自该父帧的原图、最终图或修正链。父图后来修正时保留子帧当时实际引用的父图文件身份；若追踪了 SHA，则保留真实旧值并检查其所有后代是否继承缺陷。需要修复的后代局部修正或在授权内重新生成，确认仍可用的后代保留并记入人工审查。禁止改写旧生成记录来伪造新的父图关系。

背景处理优先保留真实 Alpha；发光、半透明与软边遵守特效规则。颜色去背只限已人工确认的纯色硬边，显式使用当前硬边参数，不自动绿底。合法透明空帧表示消失/隐藏，保留帧位；整段全空拒绝。

## 打包与接入

```powershell
node <skill-dir>/scripts/images-to-atlas.mjs `
  --source-manifest evidence/animation.image-source.json `
  --project-root <project-root> `
  --output-sheet assets/resources/animations/animation.png `
  --width 128 --height 128 --anchor 384,767 `
  --animation-key animation --texture-key animation `
  --creator-resource-path animations/animation --no-remove-background
```

此例假设源画布 768×768、底部语义根为 `(384,767)`；尺寸和根点必须取当前设计值。图片命令的相对来源和输出路径均以 `--project-root` 为基准。打包从来源清单读取 FPS/loop，不能另用 CLI 覆盖，不支持独立逐帧时长。`--output-report/--output-preview` 可指定独立证据路径；输出默认拒绝覆盖，修订时使用新候选路径。区域、等比缩放、Alpha 和内容矩形/锚点变换复用视频工具语义。

图片报告使用 `cocos-image-atlas/2`，绑定来源清单路径、每帧实际图与记录，SHA 仅可选追踪、游戏时点、cell 和 Cocos 配置；不用 `video_path/source_timestamp`。报告内的 `cc` 为 `cocos-creator-frame-atlas/2` 描述清单，只说明待接入的 Creator `SpriteFrame`、`UITransform` 与 `AnimationClip`，不代表这些资产已物化。accepted 使用 `cocos-image-atlas-workflow/1`：

```json
{
  "schema": "cocos-image-atlas-workflow/1",
  "status": "accepted",
  "work_item_id": "work-item-animation",
  "candidate_version": "candidate-animation-v1",
  "settings": { "fps": 6, "width": 128, "height": 128, "remove_background": false, "anchor": { "x": 384, "y": 767 } },
  "source_manifest": { "file": "evidence/animation.image-source.json", "sha256": "sha256:<实际摘要>" },
  "quality_report": { "file": "evidence/animation.image-atlas.json", "sha256": "sha256:<实际摘要>" },
  "preview": { "file": "evidence/animation.preview.html", "sha256": "sha256:<实际摘要>" },
  "spritesheet": { "file": "assets/resources/animations/animation.png", "creator_resource_path": "animations/animation", "sha256": "sha256:<实际摘要>" }
}
```

示例摘要仅用于展示可选追踪字段；如填写，须为对应实际文件的 64 位小写十六进制值。资产继续登记 `route: frame-animation`；spritesheet 物理 PNG 在 `assets/resources/` 下并登记在 `runtime_outputs`。`creator_resource_path` 是相对 `assets/resources/` 的无扩展名标识，例如 `animations/animation`，不是 URL，须与报告 `cc.texture.creator_resource_path` 一致。通用资源清单的来源、许可和人工证据仍须填写，嵌套来源清单不会替代它们。固定 cell/透明留白属于帧动画合同，不把每个帧登记成普通静态资产来绕过帧动画文件门。若上游已经冻结为静态生成图片的 `individual/atlas_allowed=false` 合同，先按既有变更流程明确选择帧动画路线；本技能不自动覆盖该合同，也不通过虚报生产方法解除其限制。

Creator 资源导入和节点/组件/动画接入按[Creator MCP 协议](../../cocos-game-workflow-control/references/cocos-mcp-protocol.md)执行，先读取实时 `tools/list` schema；禁止手写 `.meta`、`.scene` 或 `.prefab`。`assetAdvanced_refresh_assets_and_wait` 只等待 `.meta` 存在，随后仍须按协议读回资源信息、UUID 和可发现的子资源。若当前工具 schema 无可用 `SpriteFrame` 子资源查询或所需编辑能力，停止受影响接入并报告 pending/blocked。

打包后或局部修图后重建图集、报告和预览，按实际改动重验受影响内容，摘要变化不使验收失效；需要时完成当前人工审阅再 accepted。分类、优化取舍、内部时间轴推导、逐张关键帧确认、后代缺陷审查与最终人工验收保存在设计工件，不扩展为额外报告字段。保留已修图成果，避免全序列重做。

图片序列不带视频音轨。声音按既有任务合同独立制作/接入，并绑定同一游戏事件时间轴；角色图片不默认烘入命中特效、声音或镜头反馈。V2/V3/V4 与外部操作授权继续遵守[工作流接入合同](workflow-integration.md)。
