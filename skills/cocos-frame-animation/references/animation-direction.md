# 动画导演与动作指导

在安排设计师和构思动作时读取本文件。动画导演／动作指导负责观看体验、整体表演与跨类型配合；专业设计师负责细化为对应领域的时间轴、关键状态和制作要求。岗位写入任务包与委派提示词，使用 [执行代理](../SKILL.md#执行代理) 中已有的子代理配置，不新增 `agent_type`、全局阶段或 schema。

## 按复杂度安排职责

| 任务情境 | 安排方式 |
| --- | --- |
| 单一主体、表现目标清楚、动作关系简单，当前设计师能独立完成整体构思与制作 | 由对应专业设计师兼任导演职责，在同一设计工件交付构思与细化结果，不额外启动导演代理 |
| 复杂身体表演、多主体互动、多个段落需要整体节奏设计，或角色、特效等类型需要紧密配合 | 独立委派动画导演／动作指导，先统一表演构思与关键依赖，再交对应专业设计师细化 |

主代理依据实际设计难度和协调需求选择并简述理由，不按动画时长、帧数、文件数量或是否包含某种动作设置硬阈值。简单转身也可由角色设计师兼任；复杂单类型任务仍可独立委派导演。单纯合批、批量制作或类型并列不自动增加导演岗位。制作中确需升级时，交接已有方案、素材、人工确认与当前问题，保留有效成果。

## 先构思值得观看的表演

- **观看体验与亮点。** 明确观众应感到什么、注意力如何流动、最有辨识度的变化在哪里。平静、细腻或克制也可以形成有效体验，强烈刺激和炫技不是默认目标。
- **动作与空间。** 按角色性格、对象特点和表现目的主动选择姿态对比、侧身/背身、旋转、翻腾、空间位移、透视缩短、遮挡、夸张形变等手段。它们是设计自由度，不是逐项必选动作；艺术构思可根据已有事实合理推导，不能因缺少逐项运动许可而默认正面微动。
- **节奏与配合。** 构思阶段之间的速度反差、保持、释放和收势，以及身体、衣物、道具、特效的先后关系。既有输入、命中、取消与切换权限作为玩法边界，视觉表演不自行增加伤害、触发或控制锁定。
- **制作可行性。** 先明确需要保留的表演，再依据完整运动包络安排画布、采样与批次。生成困难时先明确轨迹、补关键姿态或修正过渡；不能为了方便生成、合批或逐帧比对自动删去核心动作。效果与既有预算确实冲突时，说明受影响表现与取舍建议，沿既有方案确认规则处理。

## 导演交付与设计师交接

交付写入既有 Work Item 设计工件，不另建审批表：

1. 目标感受、表演风格、核心亮点及其与任务目的的关系。
2. 连贯的动作段落、关键姿态/视觉状态意图、空间轨迹、身体朝向演变和节奏关系；区分镜头安排、主体自身运动与资源坐标。
3. 关键事件和跨类型配合，标明主体动作、特效、道具或 UI 的职责、出现顺序、附着/接触与遮挡关系。
4. 必须保留的表现、可调整的细节、当前参数推导及实际制作限制，附完整播放时的观看重点。

独立导演先交付构思和上游事件/空间依赖，专业设计师再细化时间轴、关键状态、资源参数和类型检查点；主代理按文件所有权安排独立部分并行。设计师发现构思无法实现或与已有玩法冲突时交回导演协调，主代理裁决范围与权限，不各自简化或改写同一段表演。导演兼任时在同一工作项完成上述交接内容即可。

完整方案沿现有流程向用户说明设计理念并取得确认，导演构思与专业细化合并为当前动作方案，不额外新增导演审批门。导演不代替用户做视觉验收，主代理仍负责操作授权、接入与最终验证。

## 先看体验，再定位缺陷

真实候选和完整序列先交用户按正常速度、目标尺寸观看，检查吸引力、情绪/性格、节奏、动作亮点与主次是否成立；再逐帧定位身份丢失、无因跳变、接触穿帮、错误轨迹或事件错位。转身造成的遮挡、画面左右变化、透视缩短和设计形变按连续过程判断，不能仅因某帧不同于正面基线而否决。

导演与专业设计师依据用户反馈返修：同一目标内的调整沿现有局部返修流程；改变核心构思或目标感受仍按既有方案确认边界处理。所有视觉结论来自用户人工验收，缺少实际观看条件的项保留未验证。
