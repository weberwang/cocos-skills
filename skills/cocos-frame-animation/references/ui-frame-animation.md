# UI 帧动画

本参考只用于确实需要逐帧位图表现的按钮反馈、提示和图标。完整时间轴和播放边界遵循[完整动作与时间轴](action-timing.md)；普通 UI 动效的路由边界见下文。

## 适用范围与程序动效路由

只有视觉内容本身需要逐帧绘制，例如图标轮廓或材质逐帧变化、手绘提示状态、具有明确逐帧造型的按钮反馈，才选择帧动画路线。单纯缩放、移动、透明度变化等可由现有 UI/程序动效表达的反馈，交给项目现有 UI 与程序路线，不因项目存在抽帧工具而强制制作视频或图集。

对复合反馈先拆清视觉责任：逐帧位图负责合同指定的图形变化，程序动效负责已有 UI 路线所承担的变换。若项目合同已经规定整项反馈烘入帧图，则沿用该合同；不能自行改变职责分配。用途不决定行为单元、视频批次或 key 数；循环、单次、组合与终态保持按交互生命周期确定。反馈幅度、强调、停顿和跟随程度按状态用途与项目视觉基线决定。

## 设计依据与交付内容

UI 动效设计师负责让逐帧图形准确表达既有界面状态，并创造及时、易懂且有质感的操作体验。任务分工遵循[动画导演／动作指导职责](animation-direction.md)：简单任务由该设计师兼任导演；需独立统筹的复杂表演或紧密跨类型协作由导演提出构思，单纯类型并列或合批不自动增加岗位。设计依据包括控件已有状态、触发条件、状态切换/取消/重复触发规则及可由帧图承担的视觉责任；对照真实界面布局、控件与字体素材、目标尺寸和主题背景，确认信息层级、对比度与邻近内容。动效重点依据状态变化的重要性和既有交互反馈预期；没有明确的状态或操作权限时标待确认，不创建新的交互含义。

交付到当前 Work Item 设计工件：

- 明确希望用户获得的反馈感受、交互质感、视觉焦点和注意力节奏，说明帧动画如何提升状态表达与操作愉悦感。
- 列出本帧动画承担的状态与可见意图，标明现有触发事件、开始/结束状态，以及任务已定义的焦点、禁用或提示等相关条件。
- 描述各适用状态阶段的逐帧图形变化、关键识别时点、反馈亮点与文字/图标保护方式；可按任务选择弹性过冲、形变、旋转、材质变化等表现，说明哪些变换归逐帧图、哪些沿用程序动效。
- 说明失焦、状态切换、取消及重复触发期间如何遵循既有交互合同，并记录视觉活动范围、视觉锚点和真实点击边界约束；循环或终态按控件生命周期说明，时长、幅度和帧数由任务推导。

## 制作与优化判断

- **围绕现有 UI 状态组织表现。** 根据产品已定义的状态（例如默认、悬停/焦点、按下、禁用或提示）确认动画何时开始、结束、取消或切换。没有明确的交互状态、触发条件或打断规则时记为待澄清，不通过新增视觉状态暗示额外功能。
- **让反馈及时、有质感且可区分。** 用户触发后，视觉变化应清楚表明状态，也可通过弹性回弹、夸张变形、旋转、色彩或材质变化创造鲜明反馈；表现力度和节奏由任务目标推导，不设统一的克制风格。检查状态关键时点能被识别，避免意外频闪造成不适或妨碍操作。
- **安排信息与表演层级。** 根据观看顺序决定文字、图标与装饰的主次。关键识别时点应保留必要信息的可读性；允许过渡中出现设计好的遮挡、重叠或形变，只要不在需要判断状态时掩盖信息。小尺寸下无法识别的细节可简化，或将相应变换交给更合适的程序动效路线。
- **区分视觉运动与交互布局。** 帧图可在设计的视觉范围内移动、缩放、旋转或改变轮廓，点击边界和页面布局仍按现有 UI 合同确定。检查动作不会使用户误判控件位置或实际命中区域；透明边距、视觉锚点和布局框服务于实现，不要求画面内容静止。
- **明确结束、隐藏和取消。** 按现有交互约定判断播放到终态、恢复、隐藏或取消；状态离开、焦点改变或输入取消时不应留下过期反馈。是否循环由状态生命周期决定，不把一次按下动画当成无限循环，也不自动增加等待。
- **按像素预算优化。** 在真实 UI 尺寸和背景上检查细线、边缘、颜色对比和透明留白；移除看不清或干扰文字的装饰，避免逐帧轮廓抖动。对于只需连续的简单变换，优先由既有 UI/程序能力承担。

状态、布局边界、取消条件和逐帧处理理由记在当前 Work Item 设计工件中，不扩展报告或 accepted schema。

## 人工验收重点

1. **先完整观看反馈：** 在真实界面中连续观看动画，判断反馈是否有吸引力、质感和节奏，注意力是否被引向当前重要状态；先确认表演亮点成立，再逐帧查找实际问题。
2. **交互响应与状态辨识：** 按照已有控件状态逐项触发，确认反馈出现在正确状态，能及时表达按下、焦点、禁用或提示变化，并在状态退出后结束、隐藏或恢复；在状态需要识别的时点检查文字、图标和关键轮廓可读。
3. **视觉运动与点击边界：** 动画各帧可按设计移动、缩放、旋转、遮挡或形变；检查是否意外跳位、裁切或误导用户判断控件位置。实际布局和命中范围仍由既有 UI 合同控制，不以视觉变化推断点击区域变化。
4. **取消、切换与重复触发：** 快速离开、重新进入、失去焦点、取消输入或切换到禁用状态时，检查旧反馈不会意外覆盖新状态；播放中再次触发及快速重复触发时，核对结果符合既有规则且不会留下无意残留。行为以现有交互约定为准，未定义的边界记为问题，不由动画自行决定排队、重播或打断方式。
5. **播放方式：** 循环状态跨周期检查接缝和持续观看效果；单次反馈检查结束态和恢复/隐藏。单纯变换是否应走程序动效路线也应在验收中复核。

## 分类边界

本文件不把所有界面动画都归为帧动画。程序可表达的缩放、位移或透明度变化继续走现有 UI/程序路线；独立的能量、光效或粒子按[特效帧动画](effect-animation.md)判断；普通装饰和机关按[物件、环境与机械动画](object-animation.md)判断。若某个 UI 反馈的输入、取消或状态权限不明确，先记录待澄清，不由图形资源补充交互逻辑。
